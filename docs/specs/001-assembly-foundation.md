# Spec 001 · 玄枢装配基座：立起「家」与底座

> 状态：ready-for-agent（seam 已确认：装配契约为主 + 三份既有契约）｜日期：2026-10-11
> 依据：`docs/architecture-v1.md`、`docs/pu-spec-v1.md`、`docs/adr/0001-0005`、`docs/research/`、`product-definition.md` v10
> 钉死版本（ADR-0004）：DSH dsh-v0.2.0-rc.2 · horosa-skill v0.40.1 · 星阙桌面端 v3.11.3（仅规格参考）

---

## Problem Statement

用户没有一个「以我为中枢」的入口：打开电脑，没有一屏先看见「我是谁、今天注意什么」；没有一个把玄学底座（命+运）与自己的现实信息接起来、随时可以问事的地方；已有工具（DSH）能做软件开发，但它不认识「我这个人」。

第一步要解决的是：**把玄枢立起来**——装好玄学底座、填好出生信息、看见四卡首屏、能开一场带全套工具的问事会话，且谱可以开始积累。这是后续一切（底稿、日课、工作流、多 AI 合参深化）的地基。

## Solution

把玄枢做成一个**可安装的 DSH profile**（不 fork、纯装配，ADR-0001）：

1. 一条 setup 命令：钉死版本下载并安装 horosa-skill（本地 MCP，runtime 同版本）→ 生成 `xuanshu` profile → 装依赖 → 自检；
2. 冷启动向导：填出生信息（出生地走离线城市库 + 手动经纬双通道，时区自动含 DST）→ 调 horosa 八字出盘（`timeAlg` 缺省 0 = 真太阳时，由引擎内部换算，录入层不算）→ 落底座谱 → 命盘卡点亮；
3. 首屏 = **自我总览**（替换 DSH 首页，纯插件槽位实现）：命盘卡（只读）、日课卡、底稿卡、快捷入口（问事 / 工作区 / 工作流）四张卡；
4. **问事**：新顶层会话入口（不属于任何工作区）——勾选谱 → 说事 → 带 DSH 全套工具能力 → 会话存本地、可回看；多 AI 合参按星阙 Best-of-N 规格（规格级复用）首版实现 2 路并列 + 采用/合并/否决；
5. **谱**：可创建（AI 辅助）、可查看、可编辑、可勾选；格式按谱规范 v1（frontmatter + MD 目录 + summary）；
6. 一切数据本地文件，可整体拷走；「AI 会动你的东西」由 DSH 审批机制兜底。

## User Stories

1. 作为部署者，我想要一条命令完成安装（拉 horosa 钉死版本 + 建 xuanshu profile + 装依赖），以便于几分钟内把玄枢立起来。
2. 作为部署者，我想要安装脚本对 horosa wheel 做 SHA256 校验并强制 runtime 与 skill 同版本，以便于不装到被篡改或错配的底座。
3. 作为部署者（Windows），我想要 setup 自动把 runtime 放到纯 ASCII 根目录（`HOROSA_RUNTIME_ROOT=C:\horosa`），以便于避免中文路径导致的引擎挂起。
4. 作为部署者，我想要安装后自动自检（DSH 装配可启动、horosa 8765 健康、八字工具可用），以便于第一时间知道底座立没立起来。
5. 作为用户，我想要打开玄枢第一屏就是「自我总览」而不是工作区列表，以便于第一眼看见的是「我」。
6. 作为用户，我想要冷启动时被引导填写出生信息（出生地、日期、时间、时区），以便于把唯一的必填项立起来。
7. 作为用户，我想要出生地通过**离线城市库**选择（断网可用）或**手动输入经纬度**，以便于不依赖任何联网地理编码服务。
8. 作为用户，我想要时区随出生地自动推导（含夏令时），以便于不需要自己会算时区。
9. 作为用户，我想要八字按**真太阳时口径**出盘（引擎内部换算、我填钟表时间即可），以便于结果口径与星阙一致。
10. 作为用户，我想要出生信息确认后生成八字并点亮命盘卡，以便于底座立起、之后不再重复录入。
11. 作为用户，我想要命盘卡只读展示八字要点、点进可看详情，以便于随时瞄一眼「我的设定」而不误改。
12. 作为用户，我想要首屏有「问事 / 工作区 / 工作流」三个快捷入口，以便于从家出发去书房、车间或流水线。
13. 作为用户，我想要问事与工作区并列、不属于任何工作区，以便于「问个事」不必先建项目。
14. 作为用户，我想要开会话时手动勾选本次要用的谱（底座与底稿默认在场、不可关），以便于这次问事有依据、又不把无关信息全灌进去。
15. 作为用户，我想要在问事会话里临时挂载某个具体的工作区或工作流，以便于针对它深入提问（挂载注入时按预算裁剪并披露）。
16. 作为用户，我想要问事会话带 DSH 的全套工具能力（读文件、调工具），以便于「加载谱资料」这类事由 AI 自己完成。
17. 作为用户，我想要多 AI 合参：一个问题 2–4 路并列给出答案、可「采用 / 合并 / 否决」，以便于分歧可见、拍板在我。
18. 作为用户，我想要多 AI 合参可在设置里开关、用斜杠或按钮触发，以便于平时轻量、需要时再开。
19. 作为用户，我想要每次问事会话以本地文件保存、有一个子页面可查看历史会话并点开即读，以便于记录留存、随时回看。
20. 作为用户，我想要问事结束有「导出汇总 → 更新到谱」环节且必须我点确认才写谱，以便于 AI 不静默改我的东西。
21. 作为用户，我想要创建谱时只需打字或丢附件（MD/PDF/任意文件），AI 帮我转成固定结构，以便于低门槛地积累关于我的信息。
22. 作为用户，我想要给谱设级别（基础输入 / 可选输入），以便于控制哪些进底稿、哪些按需追加。
23. 作为用户，我想要谱列表按级别分组、可搜索筛选、点开可见（名称+描述+细节）、可直接编辑保存，以便于谱是我维护得动的东西。
24. 作为用户，我想要底稿可见（UI + MD 文档）、带来源标记（哪段来自谱/工作区/工作流），以便于一眼检视、发现提炼偏差。
25. 作为用户，我想要底稿纯派生不可手改、要改就改三个源头，以便于「关于我的汇总」永远是源头的一致投影。
26. 作为用户，我想要底稿默认定时刷新 + 随时手动刷新，以便于它不会悄悄陈旧。
27. 作为用户，我想要每日定时收到日课（当日运势 + 注意事项，时间可配），以便于玄枢主动找我、而不是只等我问。
28. 作为用户，我想要日课内容只基于底座 + 时间基准、不联网取资讯，以便于保持 local-first。
29. 作为用户，我想要登记「藏」（本地文件夹/文件的指针 + 签 + 跳转入口），以便于我的书籍、资料、密码有个统一入口。
30. 作为用户，我想要藏永远不上 AI（不读、不索引、不进上下文），以便于密码一类东西和谱安全隔离。
31. 作为用户，我想要从自我总览能进入「创建工作流」向导（会话 + 默认调用 /writing-skills + 跑通后导出 skill），以便于把办事流程固化复用。
32. 作为用户，我想要工作区/项目保持 DSH 原样，以便于软件开发能力一点不打折。
33. 作为用户，我想要多路 AI 的模型/API 配置复用 DSH 现有的 provider 配置与凭据体系，以便于不用再配一套密钥。
34. 作为用户，我想要我的全部数据都在一个本地目录里、可整体拷走，以便于「一切归你、随时带走」。
35. 作为开发者，我想要玄枢 = profile + 两个插件包 + 内置 skills + setup 脚本、零 DSH 源码改动，以便于升级 DSH 时只需重验几个补丁行。
36. 作为开发者，我想要 horosa 连接是 profile 补丁里的静态行（市场删除 UI 管不到），以便于「默认自带、不可删除」有机制保证。

## Implementation Decisions

- **装配形态**：玄枢 = DSH profile（`xuanshu`）+ 主机插件 `xuanshu-host` + 客户端插件 `xuanshu-client`（声明 `dsh.client`，自带预编译 bundle）+ 内置 skills + setup 脚本；零 DSH 源码改动（ADR-0001）。
- **首页替换**：注册新 main key `overview` + `sidebar.panellist` 首行并设为默认面板；DSH 原 `conversation` 面板保留（问事与工作区共用）；槽位遮蔽显式 priority（ADR-0002）。
- **horosa 集成**：profile 补丁静态挂 `dsh-mcp-client` 行（serverName `horosa`，回环 streamable-http `127.0.0.1:8765/mcp`，非回环不暴露）；进程生命周期由 xuanshu-host 托管（ensure runtime → spawn serve → health check）；钉 v0.40.1 + runtime 同版本 + Windows ASCII runtime 根（ADR-0004）。
- **八字录入**：出生地双通道（离线城市库 / 手动经纬），时区自动含 DST；调用 `horosa_cn_bazi_birth` 带 `agent_confirmed_settings:true` + `clarification_notes`；`timeAlg` 透传、缺省省略（=0 真太阳时，引擎内部换算，录入层不换算）；缺经纬度禁止出盘（防静默退化）。
- **问事容器**：新 main key `consult` 面板 + **玄枢自铸 sessionId 前缀**（会话分类载体，见 ADR-0009）；会话复用 DSH 事件溯源 JSONL 存储；`pus` / `mounts` 清单落旁挂文件（ADR-0009），**不塞 `meta`**（rc.2 的 `meta` 是闭集且逐字段挑，额外键静默丢弃）；临时挂载注入按预算裁剪并披露（照星阙挂载账本模式）。
- **多 AI 合参**：规格级复用星阙 Best-of-N——`/多模型` 命令；2–4 个 provider profile 或同模型四视角（classic/modern/cautious/concise，缺省经典+审慎）；N 路并行流式不带工具；judge 走**工具调用参数 JSON + 校验**（rc.2 无结构化输出，见 ADR-0010）、失败回落完成顺序第一份；采用/合并/停止；`bestOf{adoptedId,ranking,judge,costUsd}` 落旁挂文件（rc.2 无 `message.candidates` 字段，见 ADR-0009 第 7 条）；历史只带采用稿。LLM 层复用 DSH `ctx.llm` 多 adapter。
- **谱**：数据格式 = 谱规范 v1（目录 `manifest.md + 内容 + summary.md`；frontmatter `spec: pu/1` / `name` / `level` / `tags`（预留不启用）/ `source` / `updated_at`）；级别 `base|optional`、级别≠必填；加载协议 = manifest 概览 + summary 优先、按需深入。
- **底稿**：纯派生 `~/.dsh/xuanshu/digao.md`；骨架与来源标记规则生成、摘要 LLM 提炼；`ctx.schedule` daily（默认）+ 手动刷新；用户不可手改。
- **日课**：`ctx.schedule` daily（默认 07:30 可配）绑定玄枢内部系统会话投递；生成 = 内置 skill 读底座谱 + 当前时刻调 horosa 推运；不联网。
- **藏库**：`cang/registry.jsonl` 指针+签+跳转；UI 卡片以系统默认程序打开；AI 永不读内容（ADR-0003）。
- **沉淀闭环**：问事「导出汇总」→ 内置 skill 生成草稿 → 人工点「更新到谱」确认写谱；AI 不静默写。
- **安全**：问事带全套工具能力，写操作由 DSH 审批机制兜底（复用不自建）。
- **语音**：v1 不做（打字 + 附件），语音后置 v2。
- **许可证**：玄枢 AGPL-3.0-only（与 horosa 同许可）。

## Testing Decisions

**Seam 策略（一个主 seam + 三份既有契约）**：玄枢的一切能力最终表现为「装配后的 profile 对外暴露的东西」，因此测试只落在**装配契约**这一个 seam 上——用 DSH 官方 headless/sdk 宿主启动装配，断言三份既有契约，不新建任何测试通道：

1. **装配契约（主）**：启动 xuanshu profile（headless）→ 断言工具表含 `mcp__horosa__*`、玄枢自铸的会话 id 前缀与旁挂清单可读（ADR-0009 取代了原「`ctx.sessions.create` 可带 xuanshu meta」）、`ctx.schedule` 含日课/底稿任务（**前置：profile 的 bundles 必须含 `@deepseek-ai/dsh-experimental-schedule-bundle`，否则 `schedule` 行不存在且 boot 不报错**——该 bundle 只有三行：`time-context` / `schedule` / `ui-schedule`）、数据目录初始化正确、补丁行 id 未漂移。
2. **文件契约**：谱/digao/藏注册表 = 纯文件（frontmatter+MD / JSONL），断言结构与内容（谱规范 v1 即契约）；底稿骨架与来源标记 = 确定性函数，可无 LLM 测。
3. **MCP envelope 契约**：horosa 集成测试直打 `127.0.0.1:8765/mcp`（上游自己的 seam），断言 envelope `{ok,tool,version,data,summary,warnings,error}` + `technique_card` + 澄清闸拦截行为；八字用例断言 timeAlg 缺省口径。
4. **UI 槽位契约**：客户端插件组件级测试（vitest，DSH 前端链自带）——面板注册进 main key、四卡渲染、勾选谱状态；可选 playwright e2e（后置）。

**好测试的标准**：只测外部可观察行为（工具存在、文件落盘、会话 meta、schedule 注册、envelope、槽位注册），不测内部实现；断言不依赖真实 LLM 推理（LLM 相关部分以契约占位或打桩）。

**测试的模块**：xuanshu-host（装配/调度/数据初始化/进程托管）、xuanshu-client（面板组件 + 槽注册 + Best-of-N 状态机）、内置 skills（底稿骨架、谱校验、日课模板）、setup 脚本（幂等、SHA256、ASCII 根）、horosa 集成（envelope 契约）。

**Prior art**：DSH 前端链自带 vitest ^4；星阙上游有 `aiChatBestOf.test.js`（Best-of-N 单测范式可参考）；horosa 上游以 envelope 契约与 INPUT_CONTRACTS 为验收基准。

## Out of Scope

- 语音输入（v2）；签功能启用；藏的智能检索（ADR-0003 明令放弃）；
- 多用户、账号体系、云端平台；上下文冲突优先级细则；
- 工作流「测试 / 反向优化 / 复用」细流程（只做创建向导 + 导出 skill）；
- 谱/藏/定时任务管理入口的 UI 摆放、四卡视觉精修（UI 阶段）；
- 跟随上游升级（按 ADR-0004 走一次性升级）；搬运星阙代码；
- Best-of-N 超过 2 路的完整体验（首版 2 路，架构按 2–4 路预留）。

## Further Notes

- **钉版与合规**：三上游钉死版本见 ADR-0004；horosa 为 AGPL-3.0-only，玄枢同为 AGPL-3.0-only，分发需附源码与许可声明；ken 三引擎为 MIT 例外。
- **磁盘与网络**：horosa runtime 约 5GB（下载 730MB+）；setup 应支持离线 wheel 路径；本机到 github.com 当前不可达，开发期用本机已装资源（`~/.dsh/profiles/desktop` 的 rc.2 实装 + 本地 horosa 克隆）。
- **rc 风险**：DSH 尚在 rc，补丁行 id / 槽位名属内部接口——升级时重跑装配契约测试。
- **执行顺序建议**：S1 客户端构建管线 → S2 首页替换 → S3 horosa 集成 → S4 问事闭环（与 `docs/architecture-v1.md` §8 一致）。
