# Spec 003 · 体验质量线：判据、巡检与兑现率

> 状态：ready-for-agent（seam 见 §Testing Decisions）｜日期：2026-10-30

## Problem Statement

玄枢部署起来之后，第一次真正用的人给出的是这样一句话：**「UI 丑，交互逻辑严重不人性化，问题很多，没办法一条一条列举。」** 这句话里藏着一个工程事实——不是没有设计，而是设计的执行从来没人测量过：

- 设计权威其实很完整：15 屏稿（线框 / 组件树 / 交互流程 / 关键状态 / 槽位映射 / 硬约束 / 素材表 / 验收自检）、11 个 token 族、122 个 token 取值、6 档字号、`§0.4 禁则`、`§6.2 四条防脏状态规格`。
- 但这些纪律的载体是人：**「写稿人自查 / 评审人复查」**。仓库里没有任何一个检查器读得懂这些条款。
- 兑现率从未被测量：真机只被打开过两次（§16.9 / §16.10），两次都是手搓探针、看完即弃。
- 于是纪律与实现已经漂移：12 个样式注入点各写各的（7 个 `*-style.ts` + 5 处就地注入 `<style>`）、`mounts.tsx` 9 处字面 hex、全仓只 4 处消费 `--dsw-alias-*`、断点只有一个字面 `1100px`。
- 客户端测试也看不见界面：只有 `renderToStaticMarkup` 与纯函数断言，无 jsdom，点击 / 焦点 / 尺寸 / 滚动一律不可断言。

结果是**每改一轮都不知道有没有变好，也没有任何东西阻止它再坏回去**。用户的问题不是"能列出多少条"，而是"能不能被列举"——判据没有载体，问题就只能是感觉。

## Solution

建一条**体验质量线**：把已有设计权威编译成机读判据，在真实界面上采集证据，判定、算兑现率、出体验债清单；AI 只在判据范围内修复。四件事：

1. **判据集 v1**：把 `§0.4 禁则`、`§4 硬约束`、`§6.2 防脏状态`、token 字典、type-scale 升格成五列判据（`id / 判据 / 检查方式 / 证据 / 严重级`）。**没有检查器的条目必须显式标 `human-only` 并写明机器判不了的理由**——消灭"写了但没人验"。判据集带 sha256 冻结值，AI 只能写提案区。
2. **两级采集，一个判定点**：静态半边（不启浏览器）覆盖全部 30 个界面面；浏览器半边只跑**任务剧本**（首版三条：建谱 → 问事 → 藏库）。两者都只是证据采集器，判定逻辑只有一份。
3. **兑现率 + 体验债清单**：按界面面分组、按严重级排序，每条附证据；与上一次巡检做三分类 diff（新增 / 已修 / 回退），**回退单独标红**。视觉基线只进报告，不参与通过与否——所以"刷基线"不构成自证及格。
4. **判据内自动修复**：AI 改完必须过既有 `verify:all`；签字只发生在两处——判据集冻结那一次，和你本来就要批的改动 PR。

视觉方向定为**克制留白档**（用户选定：苹果式克制，而非高密度）：一屏至多一个主操作、密度 comfortable、点击目标 ≥44×44、正文 ≥16 / 行高 ≥1.5、对比度达 WCAG AA。

同时登记一个新判据族：**导航模型**。玄枢有四套入口原语（`main` 面板 / `shell.overlay` 抽屉 / `composer.dock` / 命令名），但没有"一个动作一个入口、一个返回落点"的规矩——这是"跳转不人性化"的结构性来源。

## User Stories

### 判据

1. 作为使用者，我想要每一条界面要求都能被判真假，以便于「丑 / 不好用」变成可数的清单而不是感觉。
2. 作为使用者，我想要判据全部从已有设计稿升格而来、不另写一本设计书，以便于它不会和我的设计稿打架、也不会出现第三份权威。
3. 作为使用者，我想要没有检查器的条目被显式标成"人看"，并写明为什么机器判不了，以便于不存在"写了但没人验"的灰条。
4. 作为使用者，我想要每条判据都指得出证据位置（文件行号或截图区），以便于我不信 AI 的话也能自己核。
5. 作为使用者，我想要判据带严重级，以便于先修影响面最大的那些。
6. 作为使用者，我想要判据集一旦冻结就不能被悄悄改动，以便于 AI 不能靠改考卷过关。
7. 作为使用者，我想要 AI 提的新判据只能进提案区、由我批，以便于判据的变更权始终在我手里。
8. 作为使用者，我想要判据集与设计稿冲突时以设计稿为准并回改设计稿，以便于两处不会各说各话。

### 采集

9. 作为使用者，我想要不打开浏览器的那一半先跑，以便于几分钟内就看到数字，而不是等一次长跑。
10. 作为使用者，我想要覆盖全部 30 个界面面（10 个面板 + 18 个寄生位置），以便于「全面」不是口号。
11. 作为使用者，我想要浏览器那半边只跑任务剧本、不逐屏截图，以便于这个成本我付得起。
12. 作为使用者，我想要巡检永远不写我的真实数据（真实 home 只读），以便于反复试错不会毁掉积累。
13. 作为使用者，我想要巡检前强制重建客户端产物，以便于我看到判定对应的是当前源码，而不是几天前的包。
14. 作为使用者，我想要隔离实例与桌面实例永不串味，以便于巡检不会打断我正在用的玄枢。
15. 作为使用者，我想要采集失败时如实说"没采到"而不是给 0 分，以便于我不会被假绿骗过去。
16. 作为使用者，我想要采集器对同一个界面面反复运行给出同样的证据，以便于数字可信、差异可追。
17. 作为使用者，我想要单条判据的失败能定位到具体界面面的具体位置，以便于修复不用猜。

### 判定与报告

18. 作为使用者，我想要一个数字（兑现率）告诉我这批界面面兑现了多少，以便于判断这一轮值不值。
19. 作为使用者，我想要兑现率只在同一版判据 + 同一批界面面之间可比，以便于数字不会被偷换口径。
20. 作为使用者，我想要清单按界面面分组、按严重级排序，以便于我照着顺序修就行。
21. 作为使用者，我想要每条体验债都带证据（截图 / 行号 / 计算值），以便于我三秒判断这是不是真问题。
22. 作为使用者，我想要每次巡检都和上一次对比（新增 / 已修 / 回退），以便于我知道自己是前进还是倒退。
23. 作为使用者，我想要"回退"单独标红并排在最前，以便于“改一处坏三处”当场被发现。
24. 作为使用者，我想要 `human-only` 的条目单独成一张短清单，以便于我一次过完，不用反复被打断。
25. 作为使用者，我想要报告既有给人看的版本又有给机器读的版本，以便于我能读、AI 也能接着干。

### 修复与护栏

26. 作为使用者，我想要 AI 只在判据范围内改，以便于它不会顺手把我的界面重新设计一遍。
27. 作为使用者，我想要每次修复都写清"哪条判据 / 改了什么 / 证据在哪"，以便于我能几秒决定批不批。
28. 作为使用者，我想要视觉基线只进报告、不决定通过与否，以便于 AI 刷基线不能算通过。
29. 作为使用者，我想要签字只发生在两处（判据冻结 + 改动 PR），以便于日常巡检不占用我的时间。
30. 作为使用者，我想要改动仍然要过既有的 `verify:all`，以便于体验修复不会弄坏装配与文档数字。
31. 作为使用者，我想要巡检本身只读、不动源码，以便于它永远不会成为新的不确定性来源。
32. 作为使用者，我想要 AI 越权改判据时巡检直接拒绝运行并报警，以便于我不用盯着它。

### 视觉方向（克制留白档）

33. 作为使用者，我想要界面走克制留白这一档——一屏至多一个主操作、留白优先、密度 comfortable，以便于它看起来安静而不是塞满。
34. 作为使用者，我想要点击目标不小于 44×44，以便于手指和触控板都点得准。
35. 作为使用者，我想要正文字号不小于 16、行高不小于 1.5，以便于久看不累。
36. 作为使用者，我想要对比度达到 WCAG AA，以便于弱光下也看得清。
37. 作为使用者，我想要颜色 / 间距 / 圆角一律从 token 取，以便于不再出现某处硬编码色值这种事。
38. 作为使用者，我想要同一类信息在所有界面面用同一套排版层级，以便于我不会在每个面板重新学一遍。

### 导航与跳转

39. 作为使用者，我想要同一个动作只有一个入口，以便于我不会在两个地方看到同一件事。
40. 作为使用者，我想要从抽屉 / 面板返回时回到我来的地方，以便于我不会被丢回首页。
41. 作为使用者，我想要键盘能走完一条完整任务（Tab 顺序、Esc 关抽屉、焦点可见），以便于我不必依赖鼠标。
42. 作为使用者，我想要每个界面面都有空态 / 加载态 / 错误态且说的是人话，以便于我不会对着空白发呆。
43. 作为使用者，我想要危险操作有二次确认、且确认文案说清后果，以便于我不会误删。

### 维护

44. 作为使用者，我想要这套东西自己也被既有测试门保护，以便于它不会先腐烂。
45. 作为使用者，我想要新增界面面时清单自动跟上，而不是有人记得去加一行，以便于覆盖面不会悄悄缩水。

## Implementation Decisions

**模块（名称，不是路径）**

1. **判据投影器**：读设计权威，产出版本化的机读判据集；同一输入必须产出同一字节（便于冻结）。投影器不含判定逻辑。
2. **冻结守卫**：巡检运行前的第一件事——校验判据集哈希，不匹配即拒绝运行并非零退出；这是"AI 不能改考卷"的技术封口。
3. **证据采集器 ×2**：静态采集器（Node，读源码与构建产物，覆盖 30 个界面面）；浏览器采集器（驱动隔离实例，按剧本采集）。两者输出同一种证据形状，**都不含判定逻辑**。
4. **判定引擎**：唯一判定点，纯函数 `run(criteria, evidence) → verdict[]`。任何"这条算不算过"的判断只允许出现在这里。
5. **报告器**：把 verdict[] 算成兑现率、按界面面与严重级组织体验债、与上一次报告做三分类 diff，产出人读 + 机读两份。
6. **命令面**：一条只报告、不进门的总命令，加两个子开关（只跑静态 / 只跑浏览器）。巡检不进入既有的一键校验门。

**判据的形状**

7. 每条判据固定五列：`id` / 判据（一句话，可判真假） / 检查方式（`static` · `browser` · `human-only`） / 证据（文件行号或截图区） / 严重级（`blocker` · `major` · `minor`）。
8. **硬门槛**：检查方式为 `human-only` 时必须附"机器判不了的原因"，否则投影器直接报错——不允许静默降级成 human-only。
9. 判据 id 稳定且永不复用；判据下架用墓碑标记，不删条目（否则历史兑现率不可比）。
10. 首批判据族：`T`（token 消费）· `S`（状态齐全：空 / 载 / 错）· `L`（层级与排版）· `D`（密度与点击目标）· `C`（对比度与可读性）· `N`（导航：入口唯一 / 返回落点 / 键盘可达）· `X`（文案一致性）。项目符号即 id 前缀，如 `T-004`。

**采集的约定**

11. 静态采集器覆盖 30 个界面面：10 个面板 + 18 个寄生位置（4 抽屉 / 2 设置区块 / 2 设置项 / 3 输入框 dock / 1 回合尾 / 3 命令 + …），界面面清单**只从一个事实源读**，不另抄一份。
12. 浏览器采集器首版只跑三条剧本（建谱 → 问事 → 藏库），剧本以"任务"为单位横穿多个界面面；剧本格式：步骤 + 期望命中的判据 id + 证据锚。
13. 浏览器采集前必须重建客户端产物；产物落后于源码时采集器拒绝运行并说明原因。
14. 浏览器采集只连隔离实例（独立 home + 独立端口），真实 home 一律只读；启动与握手复用既有的隔离启动与 cookie 握手能力，不新写一套启动器。
15. 采集失败与"未采到"在证据里是两种状态，绝不等价于"通过"。

**判定与报告的约定**

16. 兑现率 = 通过判据数 / 适用判据数，分母按界面面 × 判据适用范围计算；报告必须同时写出分子分母与判据集版本号，否则数字不接受。
17. 人读报告顺序固定：回退（红）→ blocker → 新增 → 已修 → human-only 清单。
18. 视觉基线只用于"这次改动有没有意外视觉变化"的说明，**不产生通过/未通过结论**；基线不进判定引擎的输入类型。

**修复通道的约定**

19. AI 的写入面：源码（判据范围内的修复）+ 提案区（新判据）+ 报告目录。判据生效区与基线目录**不在写入面内**。
20. 每次修复提交必须带机器可读的修复说明（判据 id → 改动 → 证据），缺说明的提交由检查拦住。

**视觉档位（克制留白）**

21. 密度档 `comfortable`；单屏主操作 ≤1；点击目标 ≥44×44；正文 ≥16px；行高 ≥1.5；对比度达 WCAG AA；层级只允许来自既有 6 档字号，不新增档位。

## Testing Decisions

**什么算好测试**：只测外部行为——给定判据集与证据，判定结果、兑现率数字、diff 分类、冻结拒绝、报告的字段与顺序都必须可预期。不测"某个检查器内部怎么遍历 DOM"。

**seam（本 spec 只新增一个）**

1. **唯一新 seam：判定引擎（纯函数，Node）**。静态与浏览器两个采集器都退化为"喂证据"的适配器，所以"这条算不算过"的穷尽测试只落在这一个点上——一个 seam，不是三个。
2. **复用既有 seam 两处**，不新建：
   - 装配契约（假 ctx + 静态渲染 + 界面面单事实源）作为静态采集器的输入来源；
   - 隔离实例的真实启动与 cookie 握手（`verify:isolation` 那套）作为浏览器采集器的宿主。
3. **浏览器侧只留 1 条端到端**：起隔离实例 → 跑一条剧本 → 拿到证据 → 判定引擎给出 verdict。其余浏览器场景全部用录制的证据夹具，不在测试里起浏览器。
4. **投影器**用"同一输入两跑字节相同"来测确定性；**冻结守卫**用"改一个字节必须拒绝运行"来测；**报告器**用手工构造的 verdict[] 测三分类与排序。

**先例**：`tests/assembly/**` 的"单事实源 + 契约断言"、`tests/isolation/**` 的"六门 + 真实例"、`verify:assembly` 的槽位自检。

**覆盖声明**：判定引擎与报告器是穷尽测试对象；采集器只测"输出形状与失败如实"；浏览器端到端只 1 条。

## Out of Scope

- **不改设计稿内容与 token 取值**：判据只是投影；要改设计稿走「回改本稿，不就地偏离」。
- **不做 Electron 壳的 GUI 自动化**：`docs/specs/002-reside-and-use.md:177` 的边界仍然有效（见 ADR-0015 第 8 条）。
- **不做性能 / 加载时间 / 内存判据**。
- **不做视觉重设计**：本 spec 只测量并修复判据内违规；整体视觉重做另立 spec。
- **巡检不进 `verify:all` 的门**：升级成门需另立 ADR。
- **不做多语言 / i18n 判据**。
- **不做真机 Electron 窗口验收**：沿用 §16.5 的既有边界。
- **不改 15 屏稿之外的界面**（例如 DSH 原生界面本身的观感）。

## Further Notes

- **第一批可立即计数的三类违规**（无需开浏览器）：12 个样式注入点（7 个 `*-style.ts` + 5 处就地注入 `<style>`）、`mounts.tsx` 9 处字面 hex（另有 2 处在工作流面板）、断点只有字面 `1100px`；`--dsw-alias-*` 全仓仅 4 处消费。这三类应当成为判据族 `T` 的首批用例，也是"标准先落地、注入点按违规密度收敛"的第一个可交付证据。
- **构建前置**：客户端产物不重建，实例里跑的就是旧 UI；巡检器必须显式拒绝"产物落后于源码"的状态，而不是静默采集。
- **视觉档位的由来**：使用者在「苹果式克制留白」与「高密度（Linear 式）」之间选了前者，因此判据族 `D` 的阈值按留白档取值；这条选择会影响后续所有视觉判据的方向，改动它等同于换档，需要新的 ADR。
- **导航族的已知空白**：四套入口原语（面板 / 抽屉 / dock / 命令）目前没有统一的返回落点与入口唯一性规矩；判据族 `N` 的首批三条（入口唯一、返回落点一致、键盘可达）就是为这个空白设的，第一批巡检大概率会在这里出红。
- **成本口径**：静态半边覆盖 30 个界面面；浏览器半边首版 3 条剧本。不要承诺"每屏都截图对比"——那是 150 次采集，成本与收益不成比例。
- 顺带修正：隔离启动器里关于 `--profile <p> web` 的注记已与构造命令不符（构造命令无 `web` 位置参数），随本 spec 一并改正。
