# Spec 002 · 玄枢「住进去」：独立桌面壳、两次触达、事记与多家合参

> 状态：ready-for-agent（seam 见 §Testing Decisions）｜日期：2026-10-17
> 依据：`docs/specs/001-assembly-foundation.md`、`CONTEXT.md`（事记 / 晚省 / 底稿）、`docs/adr/0013-shiji-fourth-source-of-digao.md`、`docs/adr/0014-own-desktop-shell-and-home.md`、`docs/research/spec002-resident.md`、`docs/research/spec002-multiprovider.md`、`product-definition.md` v10
> 钉死版本（ADR-0004）：DSH `dsh-v0.2.0-rc.2` · horosa-skill `v0.40.1` · 星阙桌面端 `v3.11.3`（仅规格参考）

## Problem Statement

Spec 001 把玄枢「立起来」了：profile 可装、底座可出盘、16 个功能面都在、1150 条用例是绿的。但**它没有被真正住进去**：

- 开发实例的凭据里没有任何模型 provider ⇒ 问事点了不会答；一场问事都没开过；
- 日课 / 底稿的定时任务投递过 5 次，但两个系统会话的日志只有一行 header、产物目录是空的 ⇒ 「主动触达」从未发生；
- 底稿的「自动扫描沉淀」只有骨架：工作区落一行标识、工作流恒为空 ⇒ 「越用越懂你」不成立；
- 多 AI 合参实际是同一个模型的两种视角 ⇒ 「分歧可见」名不副实；
- 玄枢只能以浏览器标签页打开，关掉页面就没有任何「它还在、它会找我」的体验。

一句话：**功能清单是全的，生活里一次都没发生。**

## Solution

把 Spec 002 定义为「**住进去**」：让部署者本人能连续三天真的用它，并从「功能通」走到「帮到了我」。

七件事：

1. **玄枢有自己的应用与家**：新增 `xuanshu-shell`（Electron 桌面壳）——独立窗口、托盘、关窗退后台、开机自启、原生系统通知；它看护自己的 DSH 实例（独立 home `~/.xuanshu`、独立端口 `19388`、独立进程）。**与 DSH 桌面版零交集，两者可同时运行。**
2. **接上 AI**：冷启动加一步——检测「能不能真的问话」（有可用 provider + 默认模型）；未接上时入口明示不可用并指路「设置 → 模型」，不允许点了没反应。
3. **两次触达**：早上 **日课**（确定性黄历/流日 + 一段 AI「今天注意什么」，可关、失败只给骨架）；晚上 **晚省**（带当天事实的提醒，点开进问事，不自动出结论）。错过的补，并标「补」。
4. **事记**：底稿的第四个来源。自动扫描工作区（项目）与工作流 → 一个项目一条「一两句摘要 + 首次扫到～最后活跃」；源头删了记录仍在；人只可删、删了永久不再自动生成。
5. **底稿两段**：「最近在做什么」+「曾经做过什么」；纯派生；不是项目档案。
6. **多 AI 合参真多家**：只读路由清单 + 2–4 路不同 provider/model + `provider::model` 去重 + 异源判官 + 跑前确认（只报规模与「金额未知」）+ 并发上限与每路超时。
7. **数据归你**：一屏「我的数据：在哪 / 多大 / 一键备份」（含会话记录，不含密钥）。

顺带补两处 Spec 001 遗留的已知缺陷：问事回看按轮渲染当前采用稿；工作流挂载接通它导出的 skill 正文。

## User Stories

### 独立与形态

1. 作为使用者，我想要玄枢是**自己的应用**（自己的窗口、自己的图标、自己的数据目录），而不是 DSH 桌面版里的一个页面，以便于它是我自己的东西。
2. 作为使用者，我想要玄枢与 DSH 桌面版**同时运行、互不干扰**，以便于我写代码的 DSH 和问事的玄枢各在其位。
3. 作为使用者，我想要玄枢**从不读写 DSH 桌面版的 home**（凭据、会话、存储都不碰），以便于两者彻底隔离。
4. 作为使用者，我想要双击玄枢图标就打开它，以便于不用记命令、不用开终端。
5. 作为使用者，我想要关掉窗口时它默认退到后台继续运行，以便于它还能在到点找我。
6. 作为使用者，我想要在设置里把「关窗口」改成真退出，以便于我需要彻底停掉它时不用去任务管理器。
7. 作为使用者，我想要托盘图标一直可见，菜单里有「打开 / 退出」，以便于随时能找回它、也能明确地关掉它。
8. 作为使用者，我想要玄枢开机自动运行（可关），以便于早上它已经在等我了。
9. 作为使用者，我想要玄枢只允许自己一个实例，重复打开只是把已有窗口叫出来，以便于不会出现两份在后台抢数据。
10. 作为使用者，我想要玄枢自己的服务挂掉时会自己重新拉起、并把状态如实显示出来，以便于不会静默地「以为它在跑」。

### 触达

11. 作为使用者，我想要早上 07:30 收到日课（时刻可调），以便于它主动找我。
12. 作为使用者，我想要日课是两段式——确定性的当日宜忌/流日（永远有）+ 一段针对我的「今天注意什么」，以便于它既可靠又像指引。
13. 作为使用者，我想要 AI 那段可以关掉，并且写不出来时只给确定性骨架、明确说「今天没有 AI 建议」，以便于不把编出来的话当命理。
14. 作为使用者，我想要晚上 21:30 收到晚省（时刻可调），里面写着当天的事实（今天几场问事、哪些项目有活动），以便于它提醒我回看今天做了什么。
15. 作为使用者，我想要点晚省就进问事，以便于想聊就聊、不想聊就关掉——它只提醒与摆事实，不替我想。
16. 作为使用者，我想要复盘说的话留在会话里，并且可以一键「存成今天的事记」，以便于关于我的材料由我决定要不要留。
17. 作为使用者，我想要关机/没打开而错过的日课与晚省在我下次打开时补上并标「补」，以便于我清楚那是过去的，不是今天的。
18. 作为使用者，我想要系统通知默认不显示具体内容（只说「今日日课已生成」），并且可以在设置里打开摘要，以便于锁屏时不泄露我的私事。
19. 作为使用者，我想要点通知能打开玄枢并停在今日视图，以便于一眼看到它想让我看的东西。
20. 作为使用者，我想要通知失败（系统关了通知权限等）时，玄枢里仍能看到未读标记与原因，以便于不会「以为它推过了」。

### 接上 AI

21. 作为使用者，我想要冷启动第二步是「接上 AI」——检测我是否已有可用 provider 与默认模型，以便于不用猜为什么问事不答。
22. 作为使用者，我想要没接上 AI 时问事入口是灰的并写清原因、一键跳到「设置 → 模型」，以便于不会点了没反应。
23. 作为使用者，我想要密钥只配在玄枢自己的 DSH 设置里一次，玄枢不另建一套密钥库，以便于不重复维护。

### 事记与底稿

24. 作为使用者，我想要底稿回答两件事：**我最近在做什么**、**我曾经做过什么**，以便于它懂的是「我」而不是我的项目。
25. 作为使用者，我想要「曾经做过什么」是一条条带日期的短记录，而不是每个项目一份档案，以便于快速扫一眼就想起那段时间。
26. 作为使用者，我想要一个项目只有一条记录（摘要随变化更新、日期是首次扫到～最后活跃），以便于列表不会越堆越乱。
27. 作为使用者，我想要项目后来删掉了，那条记录还在，以便于我的历史不会跟着文件夹一起消失。
28. 作为使用者，我想要事记只由扫描自动写入、我不能编辑它，以便于它不是我第二份要维护的账。
29. 作为使用者，我想要能删除某条事记，并且删了它就不会再自动长回来，以便于删除这个动作是算数的。
30. 作为使用者，我想要每条事记标明依据（会话几场 · 文档几份），以便于我能判断它是怎么来的、有没有编。
31. 作为使用者，我想要事记只读会话摘要与项目里的说明文档（目录白名单、可排除），不读我的代码正文，以便于它不越界。
32. 作为使用者，我想要工作流也作为「做过什么」的一个来源，以便于流水线上跑出来的东西同样进我的历史。
33. 作为使用者，我想要底稿仍然是纯派生、我不能手改（要改就改源头：谱 / 建事记的项目 / 删事记），以便于它永远是一致投影。
34. 作为使用者，我想要底稿的每一段都带来源标记（谱 / 工作区 / 工作流 / 事记），以便于我看得出哪句话从哪来。

### 多 AI 合参

35. 作为使用者，我想要合参真的并列不同家的模型（2–4 路，可不同 provider 与不同 model），以便于分歧是真的分歧。
36. 作为使用者，我想要在「设置 → 模型」里加家（含自建 OpenAI / Anthropic 兼容端点），配置一次即可用，以便于不用改代码。
37. 作为使用者，我想要玄枢能看到「我配了哪几家、每家有哪些模型、哪些家缺 key」，以便于知道合参能用谁。
38. 作为使用者，我想要判官尽量是**不在候选里**的另一家模型，以便于判官不自我偏袒。
39. 作为使用者，我想要没有异源判官时它如实说「本轮判官同源 / 判官失败」，而不是假装是异源，以便于我知道该信多少。
40. 作为使用者，我想要在跑之前看到「N 家 × 每家 model × 本次输入规模 + 金额未知」，并由我点确认，以便于我不会在不知情的情况下花钱。
41. 作为使用者，我想要某一路失败不拖累其他路，失败的那一路如实标出，以便于一份可用也算可用。
42. 作为使用者，我想要合参有并发上限与每路超时，以便于它不会把我几家的额度同时打满、也不会卡死。
43. 作为使用者，我想要采用 / 合并 / 否决仍然只在人点之后发生，并且被否决的轮次不再进入下一轮候选历史，以便于历史里只有我真正要的东西。

### 数据与回看

44. 作为使用者，我想要一屏看到「我的数据在哪、多大」，并能一键备份到我自己选的目录，以便于「一切归你、随时带走」是真的。
45. 作为使用者，我想要备份包含谱 / 藏 / 底稿 / 事记 / 会话记录，但**不含密钥**，并写清为什么，以便于我敢把它放到任何地方。
46. 作为使用者，我想要问事回看里、每一轮合参的**当前采用稿**标得出来，改选/否决后不再混淆，以便于回看是可信的。
47. 作为使用者，我想要挂载一个工作流时，模型真的看到它导出的 skill 正文，以便于「针对这个工作流深入问」是成立的。

### 验收与开发

48. 作为使用者，我想要拿一件我真在纠结的事，一口气走完「看今天 → 问它 → 多 AI 并列 → 采纳 → 沉淀回谱」，以便于验收的是它有没有帮到我，不是功能清单。
49. 作为使用者，我想要第二天不改任何东西还能同样走通，以便于它不是一次性演示。
50. 作为开发者，我想要玄枢 = 独立 home + `xuanshu` profile + 两个插件包 + 新桌面壳 + 内置 skills + setup 脚本，**零 DSH 源码改动**，以便于升级时只需重验补丁行与壳的契约。
51. 作为开发者，我想要壳与宿主之间只有一条极小的本地通知契约（回环、JSON、只有标题与可选的短正文），以便于两个进程的耦合面最小、可单测。
52. 作为开发者，我想要玄枢的所有测试都能在没有真实 LLM、没有真实 Electron 窗口的机器上跑，以便于 CI 不被环境绑架。

## Implementation Decisions

### 形态与隔离

- **玄枢 = 独立 DSH home + `xuanshu` profile + `xuanshu-host` + `xuanshu-client` + 新 `xuanshu-shell` + 内置 skills + setup 脚本**，零 DSH 源码改动（延续 ADR-0001）。
- **home 隔离**：玄枢自己的 DSH home 为 `~/.xuanshu`（可由 `XUANSHU_DSH_HOME` 覆盖；开发期仍用仓库 `.dsh-home`）。**玄枢从不读写 `~/.dsh`**（DSH 桌面版的 home），并在体检里断言这一点；DSH 桌面版仍是 `~/.dsh`。两实例各自 home / 端口 / 进程 / 凭据。（这条按 Q23「零交集」把 Q11 的「同 home」上调为「独立 home」；落 ADR-0014。）
- **端口**：玄枢 `19388`（不碰 `19387`）；horosa 仍 `8765`，按既有单占用守卫处理（谁先起谁用，另一个如要同跑走另一对端口）。
- **桌面壳**：新包 `xuanshu-shell`（Electron，自有窗口/托盘/单实例锁/开机自启）。职责只有四件：看护 `dsh --profile xuanshu --port 19388 --no-open` 子进程；承载窗口并加载认证后的 URL；托盘与关窗行为（默认隐藏、可配置为退出）；接收宿主发来的通知并展示、点击时显示窗口停在今日视图。**不实现任何业务**。
- **壳↔宿主通知契约**：壳启动时在回环上开一个仅本机可达的通知端点，把 `{url, token}` 写进一个只有宿主读得到的运行时状态文件（路径经环境变量传给子进程）；宿主在日课/晚省生成成功后 POST `{kind:'rikke'|'wansheng', title, body?, silent?, target:'overview'|'consult'}`；壳用 Electron `Notification` 展示；点击 → `show()` + 让页面回到 overview（前端无路由，做不到「点哪条进哪页」；今日视图即首页）。通知失败只记日志，**不阻塞生成、不改产物**。
- **退出语义**：关窗默认隐藏（首次关窗给一次性说明）；托盘菜单「退出」与设置里的「关窗口即退出」都走同一条真退出路径（先停子进程再退壳）；壳异常退出时子进程不留守。
- **自启**：壳通过 Electron 的登录项设置注册开机自启（可关）；打包前用启动文件夹快捷方式等价实现，并在设置页如实显示当前实际生效的方式。

### 触达

- **日课**（07:30，可调，`ctx.schedule` daily）：**确定性段**＝沿用现有黄历/流日产物；**AI 段**＝读底座谱 + 底稿「最近」+ 当日骨架生成一段「今天注意什么」；AI 段可关；生成失败或关闭时产物如实写 `ai: {mode:'off'|'failed', reason}`，界面只显示骨架。
- **晚省**（21:30，可调，`ctx.schedule` daily）：内容为**确定性事实**——当天问事场次、当天有活动的工作区/工作流、今天是否有事记更新；**不调任何模型**、不生成结论；产物落当日记录并推送给壳。
- **补课**：启动与每次到点时结算「缺失的触达」；缺失的产物可补生成/补读取，并写入 `missed: true`，界面标「补」。不把补的当天当成今天。
- **通知内容**：默认 `title` 泛化（「今日日课已生成」/「今天要不要过一遍」），`body` 为空；设置里打开摘要后才带一句不含具体私事的短句。
- **未读**：壳把通知投递结果回报给宿主（成功/失败/权限缺失），宿主落一张触达账；界面据此显示未读标记与失败原因。

### 接上 AI

- 新增只读状态面：`{configured, providers:[{id,name,keyConfigured,models:[…]}], defaultModel, reason?}`。数据来源 = `ctx.llm` 的已注册路由 + 可配置路由 + `ctx.settings` / `ctx.credentials` 的探测；任一不可得则软降级为「未知」，不编。范式沿用 DSH 会话控制器的模型目录组装与「是否配了 key」的联合判定。
- 冷启动流程变为：八字 → **接上 AI**（检测/跳转）→ 就绪；未接上时问事入口禁用并给出原因与去向，**不允许点了没反应**。

### 事记

- 存储：`<home>/xuanshu/shiji.jsonl`，schema `xuanshu/shiji@1`，一条一行；条目形状：`{schema, id, source:'workspace'|'workflow', refId, name, summary, firstSeenAt, lastActiveAt, basis:{sessions,docs}, frozenAt?, excludedAt?}`。
- **一个项目一条**：再次扫到同 `source+refId` 时**更新**摘要与 `lastActiveAt`；源头消失时写 `frozenAt` 并停止更新（条目保留）。
- **摘要依据**：该工作区/工作流的会话标题与摘要 + 项目目录里的说明文档（README / 需求 / 笔记等；目录白名单 + 用户可排除；**不读代码正文**）。摘要为目标 1–2 句、带 `basis` 计数。
- **成本控制**：仅当「依据集合」变化时重新生成摘要（内容指纹），否则只更新 `lastActiveAt`。
- **删除效力**：删除写 `excludedAt`（墓碑），之后**不再自动生成**同 `source+refId` 条目；恢复为设置里的显式动作。
- **来源两路**：工作区（项目）与工作流；工作流条的 `summary` 依据其导出的 skill 与相关会话。
- **底稿生成**：底稿在「曾经做过什么」一节渲染事记（按时间倒序，含日期区间与来源标记），「最近在做什么」一节取当前活跃项目与最近会话摘要；底稿整体仍纯派生、无写入口。
- 事件驱动：底稿刷新时顺带更新事记（同一条扫描管线，避免两处各扫一遍）。

### 多 AI 合参

- **路由清单**：新增只读 RPC（`provider → models → keyConfigured`、默认路由、可配置但未注册的路由），供设置页与合参确认页使用；数据不可得时如实显示「未知」。
- **入参**：候选从 `profileIds: string[]` 升级为 `routes: {provider, model}[]`（2–4 路，按 `provider::model` 去重）；缺 model 时才回落到该 provider 的第一个模型。
- **判官**：judge 路由必须**不在候选 provider 集合里**；找不到异源时如实标记 `judge.mode='same-source'|'failed'`，**不冒充异源**；合并槽沿用既有语义。
- **跑前确认**：新增 `estimate` 面：`{routes:[{provider,model,modelName}], inputTokens, price:'unknown'}`；金额恒为「未知」（钉版无价表，上游 cost 元数据被丢弃）；确认后才真正开跑。
- **并发与超时**：同时最多 4 路；每路独立 `AbortSignal`（含超时）；单路失败收敛为该路失败态，不影响其他路；不引入自动重试（裸 `ctx.llm.stream()` 不重试是钉版事实）。
- **沿用不变**：候选不带工具、判官不带挂载数据、历史只带被采用的稿、采用/合并/否决三闸、按轮账本与取代闸。
- **不改**：密钥存储、provider 配置的写入路径（都是 DSH 的「设置 → 模型」），玄枢只读。

### 数据与备份

- 新增 `数据` 设置页：显示 home 路径与各类数据体积（谱 / 藏 / 底稿 / 事记 / 会话 / 其它）；「一键备份」选择一个目录，产出带清单（每文件 sha256 + 大小）的备份包。
- 备份**包含**业务数据与会话记录；**不包含** `.credentials.yaml` 与任何密钥引用，页面上写明原因与「密钥怎么迁」（在玄枢自己的设置里重填）。
- 恢复口径写清：把备份内容放回 home 对应位置即可；不提供自动覆盖式恢复（避免误覆盖），只给逐项说明。

### 补两处已知缺陷

- **问事回看**：合参一稿从「全场一份」改成「各轮各一份」之后，回看需要按轮分组渲染：标出每轮当前采用稿，被否决的轮不显示为当前。服务端已有 `currentAdoptedMessageIds` 的集合语义，客户端补渲染与文案。
- **工作流挂载**：`kind:'workflow'` 的挂载层不再返回 hint 空层，改为读该工作流**已导出的 skill**（`<dshHome>/skills/<name>/SKILL.md`）作为可注入正文；读不到时如实说「这个工作流还没有导出过 skill」，不编内容。

## Testing Decisions

**好测试的标准**：只断言外部可观察的行为——装配后的服务面、落盘文件、通知端点收到的东西、壳对子进程的动作；不测内部实现；不依赖真实 LLM、真实 Electron 窗口、真实网络。

**Seam 策略（沿用两个主 seam + 新增一个宿主↔壳契约）**

1. **装配契约（主，沿用）**：以 headless 启动装配后的玄枢 profile，断言：`bazi.*` / `consult.*` / `bestof.*` / `shiji.*` / `traffic.*` / `data.*` 服务面存在，`ctx.schedule` 含日课与晚省两条 daily，附加接口面加性、补丁行 id 未漂移、**home 解析到玄枢自己的 home 且不指向 `~/.dsh`**。
2. **文件契约（沿用）**：事记 JSONL、底稿两段与来源标记、日课/晚省当日产物与 `missed` 标记、备份清单——全部是可逐字核对的纯文件；事记的摘要生成用注入的 LLM 桩。
3. **壳↔宿主通知契约（新，唯一新增）**：一条只走回环 JSON 的契约——`{kind,title,body?,silent?,target}`；用「真宿主发一条 + 假壳端点收」与「假宿主发一条 + 真壳接收模块」两侧夹住形状与语义；壳的窗口/托盘/自启只在**纯模块层**测（子进程替身 + 假 Electron 适配层），不做 GUI 自动化。**不新增 playwright/e2e 通道。**

**覆盖重点**

- 事记：项目删除后条目仍在；删除后不再自动生成；依据集合变化才重算摘要；工作流来源；底稿两段渲染与来源标记。
- 触达：日课两段式三态（有 AI / AI 关 / AI 失败）；晚省确定性事实；错过补课标「补」；通知失败不阻塞生成。
- 合参：2–4 路不同 provider/model；去重；异源判官与两种降级；跑前确认（金额未知）；单路失败不拖累；并发上限与超时。
- 接上 AI：未配置时入口禁用且有原因；配置后就绪；服务面不可得时显示「未知」而非编造。
- 回看：多轮采用稿的当前/已否决标记。
- 数据页：备份到临时目录、清单与 sha256 对账、备份不含密钥。

**Prior art**：`tests/assembly/`（真实装配 seam、注册面单一来源 `panel-surface.mjs`）、`tests/consult/`（打桩 LLM 的 Loop 级与边界用例）、`tests/rikke/` 与 `tests/digao/`（确定性链 + 时间注入）、`tests/pu/`（文件契约与沙箱）、`tests/lib/inventory-gate`（用例清单门）。

## Out of Scope

- 视觉精修（只修明显不体面处）；语音输入（v2）；签的启用；给他人分发 / 打包安装体验。
- 工作流导出的自动成稿（本期仍手填正文）；工作流「测试 / 反向优化 / 复用」细流程。
- 底稿的独立管理面板（本期事记只在底稿「曾经做过什么」一节呈现，删除动作在条目上）。
- 金额 / 价表（只报规模与「金额未知」）；自动重试与预扣费。
- 生活经历类的自动生成（「曾经」只覆盖被扫描到的工作区 / 工作流；人生经历仍由谱承担）。
- 与 DSH 桌面版的任何形式集成（不共享 home、不装进它的 profile、不接管它的端口）。

## Further Notes

- **可行性证据**：常驻/通知/壳见 `docs/research/spec002-resident.md`（钉版内无宿主/插件可达的 OS 通知通道；托盘只在桌面壳里；前端无路由；`ctx.schedule` 是进程内定时器，进程在就会跑）；多家 provider 见 `docs/research/spec002-multiprovider.md`（可 per-call 指定 provider/model、可枚举路由、无价表）。
- **两条如实登记的边界**：① 点通知只能打开窗口停在今日视图，做不到深链到某一条；② AI 日课段与事记摘要都会花模型调用，按「失败降级、不阻塞」处理，成本口径在设置页可见。
- **依赖与体积**：新增 Electron 运行时（约 200MB），仅用于壳；它不参与业务，可替换（壳↔宿主只有通知契约一条缝）。
- **钉版风险**：ADR-0004 的钉版上 `ctx.settings` / `ctx.llm` 某些面需软取（`ctx.get` 可能为 `undefined`），Shell 与宿主都按「缺席则降级/如实显示未知」实现，不假设在场。
- **开发期隔离**：ADR-0006 的双实例语义继续有效，并在此基础上收紧为「玄枢永不读写 `~/.dsh`」；`pnpm verify:isolation` 增一条 home 指向断言。
