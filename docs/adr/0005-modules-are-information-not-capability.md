# 模块是信息型系统，不承担能力；能力一律走 skill / MCP

玄枢里曾经容易被混淆的一件事：把「模块」当成「插件 / 能力」。**决定：模块只装关于「你」的资料（信息型），不干活；所有"做事"的能力一律走 skill / MCP 与执行型系统。**

能力的实际归属：

- **工作区 / 项目** 与 **工作流** —— 走 **DSH 内置的一整套 coding agent 能力**（它本来就是干这个的）；
- **问事 / 咨询** —— 走「加载模块资料 + 多 AI 合参」，它是参谋，不是车间；**但它照样带 DSH 的全套工具能力**，因为「加载谱资料」这件事本身就是读文件 / 调工具（复用同一套 coding 能力，不另写一套）。
- **模块** —— **只在「创建模块」时借用 coding 工具**（把语音 / 文字 / 附件快捷转成模块内容），**日常不参与任何执行**。

**Consequences**：模块的数据模型可以是**纯数据**（不含执行逻辑），不用考虑工具授权、沙箱、执行记录；反过来，将来要给玄枢加能力时，正确的位置是 **skill / MCP / 工作流**，**不是新建一个模块**。这条边界专门用来阻止后来的人把模块写成插件。

> 注：本文写作时用的词是「模块」，**该词随后已废弃**——现定名为「**谱**」（因为它容易被误读成「插件 / 能力」，这正是本 ADR 要防的误解）。
