# 事记：底稿的第四个来源，一份会累积、源头删了也不消失的事实记录

> 状态：accepted ｜ 日期：2026-10-17 ｜ 来自 Spec 002 的设计访谈（产品口径由用户拍板）

Spec 002 起，底稿要回答「**最近在做什么**」与「**曾经做过什么**」。原设计里底稿是**纯派生**：每次从谱 / 工作区 / 工作流重算，源头消失内容就消失。产品口径是：扫到一个项目 → 写一两句摘要 + 一个日期；**项目后来删了，那句记录还在，除非人手动删**。这与「底稿纯派生、用户不手动编辑」直接冲突，所以必须先把记录落在哪定下来，否则实现会二选一：要么丢历史，要么破铁律。

**决定：新增「事记」——底稿的第四个来源**（谱 / 工作区 / 工作流 / **事记**）。

事记 = 关于「我做过什么」的**按日期累积的短记录**：一个项目一条（一两句摘要 + 首次扫到～最后活跃的日期区间），由自动扫描写入；人**只可删、不可改**；删除是**永久**的（记住排除，项目再活跃也不再自动生成，要恢复得显式点）。底稿**仍然是纯派生**：每次重算时把事记拼进「曾经做过什么」一节，人删的是事记，不是底稿。这样两条原有铁律（底稿纯派生 / AI 不静默写谱）都不用破，新的「会累积」性质被关在一个单独账本里。

具体定值：

1. **一个项目一条**：摘要随项目变化更新；日期是**区间**（首次扫到 ~ 最后活跃）；项目消失后条目冻结，不再更新。
2. **来源两路**：工作区（项目）/ 工作流；每条记录标来源，工作区与工作流并行不混。
3. **摘要依据**：会话摘要 + 项目里的说明文档（README / 需求 / 笔记之类，目录白名单、可排除）；**不读代码正文**；条目标明「依据：会话 N 场 · 文档 M 份」。
4. **删除效力**：删除即写入排除表，之后**不再自动生成**；恢复是设置里的显式动作。
5. **底稿保持不可手改**：「删」这个动作发生在事记上，底稿只是投影。

**Considered Options**（都不选，理由记下来）：

- **底稿局部可改**：把记录直接写进底稿正文让人删 —— 破「底稿不可手改」，而且下一次重算会把删掉的行又算回来（删除没有意义）。
- **把事记做成一份自动更新的谱** —— 破「AI 不静默写谱」（写谱必须人点确认）。
- **坚持纯派生、不累积** —— 项目一删，「曾经做过什么」就消失，产品要的那个性质根本不存在。

**Consequences**：

- 底稿的「来源」不再是三路；`来源标记` 增加「事记」一路，底稿的「曾经做过什么」一节是它的唯一呈现。
- 事记是第一份「自动写入、人只删」的记录：它的扫描边界（白名单 / 排除）、摘要成本、排除表，都要在实现里落成明确的数据与隐私口径；它随数据目录一起走、可整体备份。
- 事记与「会话沉淀」不是同一件事：沉淀写谱要人确认；事记是扫描出来的事实，自动写。两条并行、规则不同，不可混谈。
- 「曾经」只能从**扫描发生之后**开始累积：启用之前的历史不会凭空出现；第一天的条目标注的是**发现日**，不是项目真实开始日（不编造）。
