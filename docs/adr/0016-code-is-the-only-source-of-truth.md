# 代码是唯一事实真源；spec / 票 / 复核报告用完即删，只留 ADR 与意图

本仓此前把三类脚手架当成了长期资产：`docs/specs/`（交付规格）、`docs/tickets/`（票面）、`docs/reviews/`（两轴复核报告），外加台账 `docs/development-status.md` 里的「票 → issue 对照」与历史验证数字。它们当初都付过账——spec 001/002/003 各自把一批「静默做不到的上游偏差」逼到台面上（ADR-0009 / 0010 / 0011 / 0012 / 0013 / 0015 全是它们的产物）。

问题在**完成之后就变成负债**：规格一旦实现，正文与代码立刻开始分叉，读者再也分不清哪一句还算数；票面与复核报告记的是「当时谁怎么想的」，不是「现在系统怎么做的」；台账里的数字靠人手抄（本仓手抄漂过四次：992 vs 1020、1811/164 → 1814/165、559944 → 560502、557338 → 558918）。三份都读得懂、都对不上代码，于是「以文档为准」这一条在实践上等于「以某一份过期文档为准」。

**决定：代码是唯一事实真源。spec / 票 / 复核报告是过程的产物，交付即删；长期只留两类文档——ADR（为什么这样定）与意图（要什么）。**

**本轮的落地范围（如实登记，与上面的「终局」分开写）**：删 `docs/specs/`、`docs/implementation/`、`docs/reviews/`；`docs/tickets/` 与 `docs/development-status.md` **保留在位**——不是因为它们被判为该留，而是因为**还有另一个会话正在依赖它们工作**（删除门槛见 Consequences 第 3 条）。两处剩余路径的处置排在那个会话收工之后，届时无需再改本 ADR 的裁决部分，只补一行执行记录。

具体定值：

1. **删掉 `docs/specs/`、`docs/implementation/`、`docs/reviews/`**（本轮执行）。它们的价值不是文本，而是**已经被代码吸收的约束**与**已经落进 ADR 的裁决**；留在仓库里只会被人当成现行规格引用。历史原文在 git 历史里可取，不需要工作树里再摆一份。
2. **`docs/development-status.md` 与 `docs/tickets/` 的终局是删除**，理由是同一套：台账承载的「票 → issue 对照」是过程记账，「验证数字」是手抄复制品——两者都是代码能自答的问题；票面是并行实现者的接口冻结件，任务结束就失去读者。**当前验证数字的长期去处只有 `README.md` 的状态段一处**，由 `scripts/check-doc-numbers.mjs` 机器核对——这一点**已经落地**（门已从「台账三个历史块」收窄成「README 一处」，见 `tests/lib/check-doc-numbers.test.mjs`）；因此台账此刻即便还在，也**已经不再承载任何被机器核对的数字**。删除它只是移除一份过期副本，不再有门依赖它。
3. **留下的「意图」清单是封闭的**：`CONTEXT.md`（术语表）、`product-definition.md`、`xuanshu-portrait.md`、`docs/architecture-v1.md`、`docs/pu-spec-v1.md`、`docs/design/`（设计稿 + 机读判据）、`docs/research/`（上游侦察证据）、`docs/runbook/`（怎么操作）、`docs/agents/`（agent 工作方式）、`docs/adr/`。**新增文档必须先回答「它是 ADR 还是意图」**；两者都不是的，写进代码注释、测试名或 runbook，不新建目录。
4. **判据的出处一律回到设计稿**。ADR-0015 第 1 条写明 `docs/design/ui-v1` 是唯一设计权威、判据是它的机读投影；但族 `D` / `C` / `N` 的 `source.anchor` 当时指向了 spec 003（因为「留白档阈值」只写在那份 spec 里），这是**已知的出处例外**（台账 §17.4 有记录）。删 spec 后该例外不再成立，因此把「视觉档位」与「导航模型」两节**回改进设计稿**（`docs/design/ui-v1/README.md` §11 / §12），判据锚随之改指设计稿并**重新签字冻结**。这不是新增规则，是把既有规则搬回它本该在的地方。
5. **规格的下游替代品是测试与 ADR**。一条实现约束要么被测试钉住（可执行），要么被 ADR 解释（为什么）；两者都没有的，视为还没落地。这条同时约束未来的 agent：**不要**再写「交付规格」文档，把要求写进测试名与断言。

**Considered Options**（都不选，理由记下来）：

- **保留 spec 但标注「已实现」** —— 已实现的规格与代码必然分叉，标注挡不住引用；本仓 §17.4 那条「唯一一处被允许的出处例外」就是被这样养出来的。
- **保留票面做历史档案** —— 票面是给并行实现者看的接口冻结件（`.scratch/notes/t08-contract.md` 那一类），任务一结束就失去读者；留在工作树里只会让新人以为那是现行接口。**本轮的「保留」不是选它，是「还没收工的会话的输入不能抽走」**（见 Consequences 第 3 条）。
- **保留复核报告做质量证据** —— 复核的结论已经变成 ADR 条款、测试用例与代码注释里的「为什么必须这样」（`docs/agents/review-checklist.md` 的每条规则都自带实例）；报告本体只是那一步的过程录像。
- **只删文本、保留目录空壳** —— 空目录会立刻被下一个人填进新文档，等于没删。
- **连 ADR 一起收进代码注释** —— ADR 要回答的是「为什么否掉了另一条路」，代码注释没有读者能沿着读的地方；决策需要一条独立的、按编号增长的链。

**Consequences**：

- `docs/` 下的目录从 9 个收成 7 个（ADR / agents / design / research / runbook / **tickets（暂留）**）；`development-status.md` 暂留。二者随并行会话收工一并退出，届时补齐本节。
- **删除会打红四处机器依赖，四处都必须先改再删**：① `scripts/ux/project.mjs` 的锚点校验（`rules/*.json` 的 `source.file` 必须存在且锚可搜到）；② `tests/ux/family-dc.test.mjs` 逐字断言 `D-002.source.file === 'docs/specs/003-…'`；③ `tests/ux/single-source-docs.test.mjs` 的允许前缀清单里含 `docs/specs/`；④ `scripts/check-doc-numbers.mjs` 的核对目标里含台账三个块。顺序是**先搬权威 → 重投影 → 重签字 → 再删目录**，反过来会得到一份锚点悬空的判据集。**本轮已按此顺序执行到第 3 步**：①②④已改并全绿（③随 `docs/specs/` 删除同步撤除，因为文件还在时撤掉会正确判红）。
- **删除是最后一步，不是第一步**：`docs/` 里的文档是**正在并行工作的其他 agent 的输入**。只要还有会话在照它们工作，删掉就是让那个会话读到 404。**裁决门槛**：删除只能在「① 四处机器依赖已改并全绿、② 没有其他会话的进行中任务在依赖这些文档」两个条件同时成立时执行；任一不成立就**保持文件在位**（它们此刻的角色是「还没收工的会话的输入」，不是「现行规格」）。
- **白名单撤除与删除必须同一个提交**：`tests/ux/single-source-docs.test.mjs` 的 `docs/specs/` 允许前缀，在文件还在时撤掉会正确判红（「真的有两份判据书」），在文件删了却留着等于给「再写一份规格」开门。所以这一条与 `docs/specs/` 的删除**同一步**执行。`docs/development-status.md` 那条白名单仍在（台账暂留），随台账删除一并撤。
- 重新签字是**人的一击**（`node scripts/ux/freeze.mjs --write --approved-by <人>`）。判据文本（statement）与阈值一字不改，只有 `source.file` / `source.anchor` 搬家——所以新 `version` 变、判据语义不变，历史兑现率在新旧版本之间**仍不可比**（ADR-0015 第 4 条口径不变）。
- `pnpm verify:all` 的文档数字门目标收窄到 `README.md` 一处；`tests/lib/check-doc-numbers.test.mjs` 随之重写（它测的是门自己，门变了必须重写，不许放宽）。
- 引用了被删目录的文档（设计稿 15 屏的「上游依据」行、runbook、ADR-0009/0012/0015、根 README 索引、`docs/agents/review-checklist.md` 的实例指针）一律改指**意图或代码**，不留悬空路径；这项工作可以与删除**同批**完成，也可以在删除前完成——但**改指针本身不删文件**，所以先做这一步不会伤到任何在跑的会话。
