## 1. 目的与入口

**它解决什么**：底稿是「关于我的精简汇总」——一个**与八字同级、默认必加载**的基础谱，由三路来源（谱 / 工作区 / 工作流）提炼而成。它**纯派生**：AI 的提炼可能有偏差，所以必须**一眼能检视**；但纠偏的地方**不在这里**，在源头。

**从哪进**：
- S1 自我总览「底稿卡」→ 点开进入本面板（票 07 交付卡片）。
- 侧栏「底稿」行（main key `digao`，order 60；D7 措辞，不写「库 · 底稿」前缀）。落位见 S15。

**去哪出**（三个源头跳转，本屏唯一的“改”的出口）：
- `[改谱 → S5]`：谱管理（手工编辑谱即可，任何编辑器均可，格式是人可读的 MD）。
- `[改工作区 → DSH 工作区]`：DSH 原样工作区 / 项目（自动扫描沉淀的对象）。
- `[改工作流 → S12]`：工作流面板（导出的 skill 与流程本体）。
- 文件形态：`[复制路径]` / `[打开所在目录]`（只读，不打开编辑器）。

**相邻屏**：S5（谱）、S12（工作流）、S15（入口落位 / C11 数据与拷走）、S1（日课与底稿卡）。

**一句话边界**：**要改就改源头**——底稿上不出现任何「编辑 / 保存 / 手动补充」的控件。

## 2. 线框

【A】底稿面板（宽 ≥1100）

```
┌─ 底稿 ─────────────────────────────────────────────────────────────────────────────
│ ① 纯派生 · 不可手改      ② 要改就改源头：[改谱 → S5] [改工作区 → 工作区] [改工作流 → S12]
│ ③ 上次刷新 2026-10-11 07:30 · 下次 2026-10-12 07:30（来自定时任务）
│ ④ [刷新]    ⑤ [⋯ 复制路径 / 打开所在目录 / 查看 MD 形态]
│ ⑥ 本面板没有编辑框、没有保存按钮：内容由「规则骨架 + AI 摘要」生成；改了源头，刷新即变
│
│ ⑦ 来源分组（三路并行不混；每组带来源标签与计数）
│  ┌▎来源：谱（4 段 · 骨架=确定性函数 · 摘要=AI 提炼）──────────────────────────────
│  │ ▎[谱] 事业与行业 ▸ 近一年判断
│  │    今年以稳为主；4—6 月有一次岗位变动，适合先谈条件再定去留。
│  │    源自：pus/事业与行业/内容.md（updated_at 2026-10-11）
│  │ ▎[谱] 技能与工具 ▸ 常用链
│  │    …
│  ├▎来源：工作区（2 段）──────────────────────────────────────────────────────────
│  │ ▎[工作区] xuanshu（本项目）· 扫描于 2026-10-11 07:30
│  │    …
│  ├▎来源：工作流（1 段）──────────────────────────────────────────────────────────
│  │ ▎[工作流] weekly-industry-digest · skill 来源 user-dsh
│  │    …
│  └▎合计 7 段 · 1,208 字 · 生成器：骨架=xuanshu:refresh-digao（无 LLM）· 摘要=LLM 提炼
│
│ ⑧ 文件（只读）：~/.dsh/xuanshu/digao.md     [复制路径] [打开所在目录]
└────────────────────────────────────────────────────────────────────────────────────
```
**线框说明（A）**：① 顶部固定标记「纯派生 · 不可手改」，位置在标题行，**不随滚动消失**（吸顶）。② 三个源头跳转是「要改就改源头」的落地，三枚按钮并列。③ 时间信息两枚：上次刷新 / 下次定时刷新（值来自 `ctx.schedule` 里底稿任务的 `scheduledAt`）。④ 本面板**唯一的功能按钮**：`[刷新]`。⑤ 只读类动作收进「⋯」（复制路径 / 打开所在目录 / 查看 MD 形态），**没有一个动作会写入底稿内容**。⑥ 负向声明（评审验点）。⑦ 来源分组区：见下【B】的来源标记方案。⑧ 文件路径只读展示。

【B】来源标记的线框细节（**分组 + 边条 + 行内标签**三层）

```
┌▎来源：谱（4 段）──────────────────────────────────────────────────────────────────
│  ▲ 组头 = 组级边条（左） + 来源名 + 计数 + 生成方式（骨架规则 / 摘要 AI）
│
│  ▎[谱] 事业与行业 ▸ 近一年判断
│  ▲    ▲ 行内来源标签（拷贝到 MD 后仍然可见）
│  ▲ 段级边条（左，与组级边条同族、更深一档）
│  │    今年以稳为主；4—6 月有一次岗位变动……
│  └    源自：pus/事业与行业/内容.md（updated_at 2026-10-11）
│
│  ▎[谱] 技能与工具 ▸ 常用链
│  └    …
└────────────────────────────────────────────────────────────────────────────────────
```
**线框说明（B）**：
- **分组（主）**：三路各成一组，组头写「来源：谱 / 工作区 / 工作流 + 段数 + 生成方式」。理由：产品定义 #4 要求「分开标注、并行不混」——分组能让「哪一路这轮没内容」一眼可见（组头显示 `0 段`），而不是被混进一段连续正文里看不出来。
- **边条（辅）**：组级边条 + 段级边条（同族、段级深一档）。理由：底稿可能很长，滚动时组头会离开视野，边条让人在长列表里仍能追踪「我现在读的是哪一路」。
- **行内标签（必需）**：每段首行带 `[谱] / [工作区] / [工作流]` 标签 + 段末「源自：<具体文件或实体>」。理由：底稿的纯文本形态 `digao.md` 是要被 AI 读进上下文的，也是人可能直接打开 MD 看的——**来源标记必须活在 MD 文本里**，不能只活在这屏的视觉分组上。
- 三层同源同义：三层都由**确定性规则**生成（骨架与来源标记规则生成，可无 LLM 测），标签文字与 MD 里的标记逐字一致，因此「界面看到的来源」= 「AI 读到的来源」。

【C】窄屏（<1100）

```
┌─ 底稿 ─────────────────────
│ ① 纯派生 · 不可手改
│ ② 改源头：[谱][工作区][工作流]
│ ③ 上次 10-11 07:30 · ④ [刷新]
│ ⑥ 没有编辑框、没有保存按钮
│ ⑦ ▎来源：谱（4 段）
│     [谱] 事业与行业 ▸ 近一年…
│      今年以稳为主……
│    ▎来源：工作区（2 段）…
│    ▎来源：工作流（1 段）…
│ ⑧ ~/.dsh/xuanshu/digao.md
└────────────────────────────
```
**线框说明（C）**：窄屏只做堆叠；① 标记与 ⑥ 负向声明**不折叠**；段级边条在窄屏降为行首一枚来源标签（`[谱]`），保证「哪段来自哪路」不丢。

【D】陈旧态（追加态，宽屏下的表现）

```
┌─ 底稿 ─────────────────────────────────────────────────────────────────────────────
│ ⚠ 源头已变：谱「事业与行业」自 2026-10-11 07:30 后更新过（1 个来源 · 上次刷新前）
│   → 当前底稿可能陈旧（stale）        [立即刷新]     [先看差异说明 ▸]
│ ① 纯派生 · 不可手改  ② 要改就改源头：[改谱 → S5] [改工作区] [改工作流]
└────────────────────────────────────────────────────────────────────────────────────
```
**线框说明（D）**：横幅出现在顶部、在 ① 之上；`[先看差异说明 ▸]` 只展开「哪些来源变了」（改了哪个文件、什么时候变的），**不显示差异正文的编辑入口**——因为本屏不可改。

## 5. 交互流程

1. 人从 S1 底稿卡或侧栏「底稿」进入（触发：点击）→ 系统读 `~/.dsh/xuanshu/digao.md` 并按来源标记解析分组 → 界面：`loading`（骨架先出）→ `ready`。**【副作用】** 无（纯读）。
2. `ctx.schedule` 的 daily 任务触发（触发：定时）→ **【副作用】** 内置 skill `xuanshu:refresh-digao` 跑一次：读三源（base 级谱、工作区扫描、工作流产物）→ 规则拼骨架与来源标记 → LLM 提炼各源摘要 → 原子替换 `~/.dsh/xuanshu/digao.md` → 界面：若面板正开着，静默重载并保留滚动位置，③ 的「上次刷新」更新。
3. 人点 `[刷新]`（触发：按钮，**不是**改底稿，是重算）→ **【副作用】** 同上（手动触发的一次重算）→ 界面：`running`（按钮转「刷新中…」+ 顶部细进度）→ `done`。
4. 人点 `[改谱 → S5]`（触发：按钮）→ 跳 S5 谱管理；人**在那里**改谱 → 回到本面板点 `[刷新]` → 界面：内容随源头变化（这就是「要改就改源头」的完整回路）。
5. 人点 `[改工作区]` / `[改工作流]`（触发：按钮）→ 跳 DSH 工作区面板 / S12 的工作流面板（main key `workflow`）；工作区 / 工作流的产物经**自动扫描沉淀**进底稿（**默认自动、无人工闸门**，与问事的会话沉淀是两条并行机制）。
6. 源头在上次刷新后被改动（触发：文件 `updated_at` 变化）→ 界面：顶部出 `stale` 横幅（D）；`[立即刷新]` 走步骤 3；**不给编辑入口**。
7. LLM 摘要失败（触发：模型不可用 / 摘要被拒）→ 界面：`error` 但**骨架仍在**——段落照常按来源分组显示，摘要位置标「摘要未生成」+ `[重试摘要]`（骨架是确定性函数，不依赖 LLM，所以底稿不会整块空掉）。
8. 人点 `[查看 MD 形态]`（触发：按钮）→ 界面：只读预览该文件的纯文本形态（同一份内容，展示来源标记在 MD 里长什么样）；**不提供编辑器**。

## 6. 关键状态

| 状态 | 触发条件 | 界面表现 | 可执行动作 |
|---|---|---|---|
| `empty` | 三路来源都没有内容（刚装好、谱还没填、没有工作区产物） | 空态写「为什么是空的：底稿由谱 / 工作区 / 工作流提炼而成，现在三路都没有内容」+ 主按钮 `[去建第一个谱（S5）]` + 次按钮 `[去创建工作流（S12）]` + 一行「底稿会自动刷新，不用手动填」 | 跳 S5 / 跳 S12 |
| `loading` | 首次打开、或读 `digao.md` 中 | 组骨架屏（三组各出骨架，不整页转圈） | 无 |
| `ready` | `digao.md` 已解析 | 三组内容 + 时间信息 | `[刷新]` + 只读动作 + 三跳转 |
| `error` | 文件不可读 / 摘要失败 | 分两级：文件级错误写明路径与原因（`[重试]`）；摘要级错误**保留骨架**并逐段标「摘要未生成」 | 重试 / 重试摘要 |
| `stale`（陈旧） | 源头在上次刷新后变更 | 顶部横幅：哪个来源变了 + `[立即刷新]`（D） | 立即刷新 / 看差异说明 |
| `running` | 正在重算 | `[刷新]` → 「刷新中…」；已有内容**保持可读**（不清空） | 无（可继续读） |
| 只读态（恒为真） | 本屏任何时候 | 无编辑框 / 无保存按钮；⑥ 声明常在 | —— |
| 窄屏态 | 宽 <1100 | 单列；标记与声明不折叠；段级边条降为行首标签 | 同 `ready` |

## 9. 硬约束在 UI 上的呈现

本屏矩阵（README §5）：**C2 ●**、**C11 ○**；其余不涉及。

**C2 底稿只读（纯派生）**
- 顶部固定标记，**逐字**：「纯派生 · 不可手改」（与 S1 / S4 底稿卡上的徽标逐字一致 —— 跨屏一致性硬要求）；吸顶、无关闭按钮；配色只走 `--xs-constraint-derived-fg/-bg`。
- 「要改就改源头」三个跳转并列在标记右侧：`[改谱 → S5]`、`[改工作区 → 工作区]`、`[改工作流 → S12]`。
- **唯一按钮是 `[刷新]`**：面板上没有第二个功能性按钮；只读动作（复制路径 / 打开所在目录 / 查看 MD 形态）收在 `[⋯]` 里，且都不写内容。

**C11 一切数据本地、可整体拷走（○ 涉及处）**
- 底稿本体就是一个本地文件：`~/.dsh/xuanshu/digao.md`，路径在 ⑧ 只读展示，随 `~/.dsh/xuanshu/` 整体拷走；拷走后新机器上打开本面板即读到同一份内容（完整拷走说明在 S15「数据与拷走」内页）。
