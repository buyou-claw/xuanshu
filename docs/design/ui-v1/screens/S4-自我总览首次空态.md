## 1. 目的与入口

**目的**：冷启动第一天（setup 跑完、horosa 已就绪、`~/.dsh/xuanshu/pus/_base/bazi.md` 还不存在）打开玄枢时，看到的**不是**四张空白卡加一句「暂无数据」，而是**一张明确告诉你「只差一件事」的屏幕**——把唯一的必填项摆到正中央，一次点进去就能立起底座。

**触发条件（三个同时成立才进入本屏）**

1. profile 装配可启动（S1 spike 通过）；
2. horosa 进程健康（`127.0.0.1:8765/mcp` 可用）——未就绪时见 §6 `error`；
3. `~/.dsh/xuanshu/pus/_base/bazi.md` **不存在**（底座未立）。

**从哪进**：启动 `dsh --profile xuanshu web` → 落地即本屏（同 S1，默认面板仍是 `overview`）；或从任意面板点侧栏「家」返回。

**去哪出**

| 控件 | 落到哪 |
|---|---|
| ① `[开始填写出生信息 ->]`（命盘卡空态主按钮） | **S3 第 1 步**（唯一必填项的入口） |
| ③ `[开始填写出生信息 ->]`（底稿卡空态按钮） | 同上（底稿卡**不提供**「刷新」——没有源头可提炼） |
| ② `[立即生成]` | 就地触发日课生成；底座未立时会失败 → §6 `error` 分支，**引导先立底座** |
| ② `[改时间 -> S14]` | S14 日课与定时任务 |
| ④ `[问事]` | S6 问事面板（可进，但副标题明说「底座未立 · 会先引导你填出生信息」） |

**与 S1 `ready` 态的差异（本屏的存在理由）**

## 3. 线框说明

> 线框内一律用 ASCII 符号（`-` 代替 `·`、`->` 代替箭头），以便 diff 与终端阅读；C1 / C2 要求的正式标记与空态文案在 §3 与 §9 逐字给出。

- ① **命盘卡（主角）**：插画 + 标题「底座还没立起来」+ 一句解释「填一次出生信息，命盘就点亮了」+ 主按钮 `[开始填写出生信息 ->]` + 一行代价说明「预计 1 分钟；之后不再重复录入」。**不做**「跳过」按钮——底座是唯一必填项，跳过等于玄枢没有地基。
- ② **日课卡**：文案必须写出因果——「今天还没有生成日课。日课默认每天 07:30 生成。」两个按钮：`[立即生成]`（点了会失败 → §6）与 `[改时间 -> S14]`。卡内一行小字「（底座未立时生成会失败）」把结局提前说清，让用户自己决定要不要点。
- ③ **底稿卡**：文案 = 「底座未立，还没有可提炼的来源。」+**「这里不会先有内容：提炼源是 0。」** 唯一按钮 `[开始填写出生信息 ->]`。底稿卡上**没有 `[刷新]`**（S1 ready 态才有）——这是与 S1 最需要被看清的一处差异。
- ④ **快捷入口卡**：三格全部可用（工作区 / 工作流不依赖底座）；问事格副标题改为「底座未立 · 会先引导你填出生信息」。卡内仍常驻边界句「谱 / 藏 / 定时任务是管理入口，在侧栏「库」与设置里，不在本卡」（与 S1 一致，C6 ○）。
- ⑤ **页眉**：与 S1 同款，仅标题后缀不同（「家 · 自我总览 · 首次空态」）+ 括号内「数据都在本地」（C11 ○ 的轻量呈现；完整说明仍在 S15）。
- ⑥ **D2 的落地**：本屏四卡仍是**卡级**状态机；日课卡 / 底稿卡进入 `loading` 时各自出骨架，**没有整页 loading**（与本屏的空态并存：①③ 恒空，②④ 各自独立）。

## 5. 交互流程

1. **落地本屏** → 探测两件事：`~/.dsh/xuanshu/pus/_base/bazi.md` 是否存在、horosa 是否健康 → 判定为「冷启动」→ 四卡渲染为冷启动形态。**无副作用**。
2. 点任一 `[开始填写出生信息 ->]` → 打开 **S3 第 1 步**（同一个 `XsOnboardingLaunch`，与 S1 空态按钮行为完全一致，不出现「两个入口两种行为」）。
3. 点 ② `[立即生成]` → **【副作用】**触发 `xuanshu:rikke`：读底座谱（**此时不存在**）→ 失败 → 界面 `error`：「日课需要底座：先填出生信息」+ `[开始填写出生信息 ->]` + `[改时间 -> S14]`；**不产生半成品日课卡**。
4. 点 ② `[改时间 -> S14]` → 进 S14（定时任务管理；冷启动期也可以先把 07:30 改成自己要的时刻）。**无副作用**。
5. 点 ④ `[工作区]` → DSH 原工作区（原样，可正常建项目 / 开会话 / 跑工具）；点 ④ `[工作流]` → S12 向导（**S12 负责** `ctx.sessions.create` + seed 调 `/writing-skills`）；点 ④ `[问事]` → S6（**S6 负责**开会话 + `meta.xuanshu`），S6 在底座未立时先给一句引导再进会话。
6. **离开本屏**的唯一常规路径 = 完成 S3（**【人工确认闸门】**出盘 + 落底座谱 → **【副作用】**写 `~/.dsh/xuanshu/pus/_base/bazi.md`）→ 回到 `overview`，四卡切到 S1 `ready` 形态（命盘卡点亮）。**本屏自身不写任何文件。**
7. **反向路径**（底座谱被删 / 读不到）→ 下次落地时重新判定为冷启动 → 回到本屏；此时 ④ 的问事格副标题重新出现「底座未立」提示（状态一致，不留脏）。

## 6. 关键状态

| 状态 | 本屏表现 |
|---|---|
| `empty`（本屏主态） | 如上 §2：①③ 恒空且**可执行**，② 空态可执行但提前声明会失败，④ 有内容。每张卡都写「为什么是空的」+ 下一步按钮 + 指向哪（S3 / S14 / S6 / S12） |
| `loading` | 落地时的**探测期**：命盘卡与底稿卡各出**卡级骨架**（不整页转圈，D2）；探测完成即切 `empty` 或 `ready`（若底座其实已存在，直接进 S1 形态，**不闪一下空态**——探测结果先到先渲染，用一次落定避免闪烁） |
| `error` | 分两种并各自可执行：**(a) horosa 未就绪**（`mcp__horosa__*` 不可用 / 8765 健康检查失败）→ 全屏顶部一条提示条「底座（horosa）没起来：先跑 setup 或看排查」+ `[重新检测]` + `[去排查 -> S15]`；四卡仍渲染为冷启动形态（**不整屏失败**，用户可以先去工作区干活）；**(b) 生成日课失败**（点 ② 后）→ 日课卡 `error`：「日课需要底座：先填出生信息」+ `[开始填写出生信息 ->]` + `[改时间 -> S14]` |
| 禁用态 | ③ 底稿卡的 `[刷新]` **不存在**（不是置灰——没有源头时刷新是假动作）；① 命盘卡不提供 `[看详情]`（无盘可看，不给置灰按钮占位） |
| 陈旧态 `stale` | 不适用（冷启动期没有可陈旧的内容）；若探测到 `_base/bazi.md` 存在而界面仍停在冷启动形态 → 视为探测缓存问题，下一次落定即修正（不留脏态） |
| 窄屏态 | 单列 + D3 顺序（§2.2）；插画缩为装饰；底稿卡不显示「要改就改源头」 |
