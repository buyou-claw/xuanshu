# S10 · 沉淀确认（导出汇总 → 更新到谱）

> 归属票：15 ｜ 层级：会话内区块（问事会话的收尾环节；**只在 DSH 原生 `conversation` 面板在屏时渲染** —— 定案 D5 / 事实 F1） ｜ 槽位：主挂载 `conversation.chat.turnTail`（list/session）；入口落 `conversation.composer.dock`（list/session）；备选「沉淀记录需回放」→ `ctx.uiConversation.events.register()` + `conversation.chat.node`（keyed/session）；确认弹窗为**自研对话框外壳**（照 `Modal` 形状与行为）；通知落 `shell.overlay`（list/root）——键名以 `shared/DSH槽位映射.md` 为准
> 上游依据：`docs/specs/001-assembly-foundation.md` §Implementation Decisions「沉淀闭环」（用户故事 20）；`docs/architecture-v1.md` §5/§6/§7；`.scratch/assembly-foundation/issues/15-sediment-confirm-write.md`；`docs/pu-spec-v1.md` §7
> 规格级复用来源：无（沉淀闸门是玄枢自有机制；草稿卡与弹窗都是照 DSH 形状自研，不 import）
> 本屏不做什么：不编辑谱（那是 S5）、不做「自动扫描沉淀」（工作区 / 工作流 → 底稿，无人工闸门，见 S13）；**不提供任何 AI 自动写谱的路径**。

## 1. 目的与入口

**它解决什么**：一次问事结束后，把成果留成下一次的基础信息——但**写入必须由人点**。这是「AI 会动你的东西」这件事上，唯一由人端着的闸门（铁律 2 / 铁律 5）。

**从哪进**：
- 问事会话（在 DSH 原生 `conversation` 面板里）收尾条上一枚 `[导出汇总]` 按钮（落 `conversation.composer.dock`）；**仅当会话 meta 为 `xuanshu.kind='consult'` 时注册**（工作区会话里不出现）。
- 可选：会话内斜杠命令（命令名 **(需确认)**，实现票定；不注册也算满足本稿）。
- 从 S7 历史回看打开旧会话 → 同样可补一次「导出汇总」。

**去哪出**：
- 写入成功 → 结果通知（`shell.overlay`）→ 一键跳 S5 谱管理看更新后的谱。
- 「只导出，不写谱」→ 导出文件留在 `~/.dsh/xuanshu/exports/`（**(需确认)** 最终目录名，实现票定），本屏给「打开所在目录」。
- 放弃 → 草稿留在 `~/.dsh/xuanshu/sediment/`（草稿区，**不在谱目录里**，因此不构成「已写入」）。

**相邻屏**：S6（宿主）、S7（回看）、S5（谱）、S13（底稿下次刷新后反映）。

**一句话边界**：本屏是**人的闸门**，不是 AI 的输出通道——AI 只能产出草稿，写入动作只由人在弹窗里点。

**落法先说清（D5 / F1 的直接后果）**：沉淀整套（入口条、草稿卡、确认弹窗、审批卡）**都长在会话语境里**，因此必须落在 DSH 原生 `conversation` 面板承载的那场问事会话上：
- 从 **`consult` 门厅**（S6 面板）发起沉淀时，先 `ctx.layout.selectPanel(null)`（D6：契约是「显示当前会话」）切回 `conversation` 面板，再出现 `[导出汇总]` 与后续区块；**不在 `consult` 面板里画确认弹窗**（那里的 `conversation.*` 子槽全不渲染，F1）。
- 同理，**审批卡只在 `conversation` 面板可见**（它是 `conversation.composer` 的 chain 顶替）——这也是把沉淀放在会话语境里的第二个理由（C10 要看得见）。
- 草稿内容属于「当前态」而不是会话历史 → 走 list 槽（`conversation.chat.turnTail` / `conversation.composer.dock`）；若将来要让「这次沉淀」本身进会话历史并可回放，再走 `ctx.uiConversation.events.register()` + `conversation.chat.node`（§6.7 的两条正统路径）。

## 3. 线框说明

- ① `[导出汇总]` — 唯一入口，人点；出现条件 = 会话是问事；工作区 / 工作流会话不注册。
- ② `[临时挂载 ▸]` — S8 的入口在此位置复用，本屏不改其行为。
- ③ 草稿卡 — `turnTail` 区块；首行固定披露「字 · 未写入」；预览只读。
- ④ `[更新到谱…]` — 只开弹窗，**不写**。
- ⑤ `[只导出，不写谱]` — 落导出文件，**不碰谱**；事后仍可从草稿卡再发起 ④。
- ⑥ `[丢弃这份草稿]` — 删草稿文件，退出本次沉淀；会话本身不受影响。
- ⑦ 负向声明 — 界面上不存在 AI 自动写入入口（评审验点，见 §9）。
- 弹窗 ①–⑥ — 目标谱 + diff + 字数 + 只读路径四项齐全，缺一即不合格。
- 状态点 — 草稿卡右上角的 `empty / loading / ready / error / stale` 文字标记（见 §6）。

## 4. 组件树

> **写法规矩（F4/D9）**：本节一律写「**照 X 形状自研**」——不 `require` `@deepseek-ai/dsh-client-ui-primitives` 或任何 Harness Client 包；类名走 `--xs-` 前缀，样式只保留 `--dsw-alias-*` / `--xs-*` token 引用。下表括号里给的是**形状来源**，不是可 import 的依赖。

- `XsSedimentEntry`（自研）— 会话收尾条上的入口按钮；仅在 `meta.xuanshu.kind === 'consult'` 的会话里注册；槽位 `conversation.composer.dock`（list/session；备选 `conversation.session.header.utilities`，也是 list/session）。
- `XsSedimentDraftCard`（自研）— 草稿卡外壳；槽位 `conversation.chat.turnTail`（list/session，`id: xuanshu.sediment-draft`，`order: 30`）——该槽语义正是「已完成轮次后的贡献」，已装先例 deliverables / plan / schedule。
  - `XsSedimentStatusBadge`（自研）— 状态标记 + 字数 + 「未写入」披露（形状照 DSH 的只读 Tag；配色走 `--xs-constraint-human-gate-*` 的容器位）。
  - `XsSedimentPreview`（自研）— 只读预览（照 DSH 的只读文本块形状 + 原生 `overflow` 内滚；DSH 无 `ScrollArea` 原语）。
  - `XsSedimentActions`（自研）— 三个按钮（照 DSH 主 / 次按钮形状与行为）。
- `XsSedimentConfirmDialog`（自研）— 确认弹窗外壳自研（照 `Modal` 的形状与行为：焦点管理、遮罩、Escape；DSH **没有**确认闸门组件），六个部件：
  - `XsPuTargetPicker`（自研）— 目标谱 + 分节选择；数据源与 S5 共用（谱文件系统）；含「新建谱…」跳转。
  - `XsSedimentDiff`（自研）— 逐段 diff 视图；输入 = 草稿正文 + 目标谱正文；记号 `+ / ~ / =`；**纯展示，不提供编辑**（形状照 DSH 的 `DiffBlock`：折叠 + 统计）。
  - `XsWordDelta`（自研）— 字数变化（前 → 后 / 差值 / 比例 / summary 单列）。
  - `XsReadonlyPathList`（自研）— 写入路径与备份路径的只读展示 + `[复制路径]`（形状照 DSH 的行内动作；用 `text-code` 呈现路径）。
  - 确认按钮区（自研）— 形状照 DSH 的显式把关控件（勾选 / 明确点按），**不用**一句提示文案代替闸门。
- `XsSedimentNotice`（自研）— 结果通知；槽位 `shell.overlay`（list/root，加性；只放通知类条目）。
- **不自建**：审批卡 —— 它是 DSH 的 `conversation.composer` chain 顶替，玄枢**不实现、不上色、不加开关**。
- **归属检查**：每个节点都落在上表槽位或父组件内，无孤立节点；本屏不新增任何 main key，也不占用任何 `conversation.*` 的 single 槽。

## 5. 交互流程

1. 人在问事会话里点 `[导出汇总]`（触发：按钮，位于 `conversation.composer.dock`）→ 系统：读本次会话事件日志（`~/.dsh/sessions/`，与 S7 同一份）→ 界面：草稿卡出现，状态 `loading`。**前置**：`conversation` 面板须在屏（从 `consult` 门厅进来时先 `ctx.layout.selectPanel(null)`，D5/D6）。
2. 系统调内置 skill `xuanshu:sediment` 生成草稿（触发：系统）→ **【副作用】** 草稿写入 `~/.dsh/xuanshu/sediment/<会话id>.md`；该写入由 AI 发起，**走 DSH 审批卡**（不自建）→ 界面：草稿卡状态 `ready`，首行显示「1,842 字 · 尚未写进任何谱」；审批未决时卡片转 `disabled` 并写明「有一次待处理的写入审批」。
3. 人点 `[更新到谱…]`（触发：按钮）→ 系统：读目标谱当前正文与草稿正文做逐段 diff、算字数 → 界面：确认弹窗打开，状态 `ready`（弹窗内）。
4. 人在弹窗里选目标谱 / 分节、看 diff 与字数变化（触发：人在读）→ 界面：无副作用；若此时目标谱文件被外部改动 → 弹窗顶部转 `stale`：「目标谱在预览后被改动，请重新生成预览」+ `[重新预览]`。
5. 人点 `[确认更新]`（触发：按钮，**【人工确认闸门】**）→ **【副作用】** 宿主侧写入：先备份，再原子替换 `~/.dsh/xuanshu/pus/<谱名>/内容.md` 与 `summary.md` → 界面：弹窗关闭，草稿卡转 `done`，`shell.overlay` 出通知「已更新到谱「事业与行业」（+638 字）· [查看谱]」。
6. 若人选 `[只导出，不写谱]`（触发：按钮）→ **【副作用】** 导出文件落 `~/.dsh/xuanshu/exports/`（未确认草稿留在 `sediment/`）；谱文件未被触碰 → 界面：草稿卡转 `done`（标「仅导出」）。
7. 若人选 `[丢弃这份草稿]` → **【副作用】** 删草稿文件 → 界面：草稿卡消失，状态回 `empty`（可再次 ①）。
8. 「新建谱…」（触发：按钮）→ **跳 S5 的 `pus` 面板内视图（创建谱子页，不占浮层、不新开 main key）**；创建完成后回到本弹窗并自动选中新谱。
9. 写入失败（磁盘满 / 权限 / 目标谱被占用）→ 界面：弹窗保留，转 `error`，写明失败的路径与原因，`[重试]` 只重试写入（不重跑草稿）。

## 6. 关键状态

| 状态 | 触发条件 | 界面表现 | 可执行动作 |
|---|---|---|---|
| `empty` | 会话未导出过汇总 | 收尾条只有 ①；草稿卡不出现 | ① 导出汇总 |
| `loading` | ① 之后，skill 正在生成草稿 | 草稿卡出骨架屏（**不是**整页转圈） | 无（可关会话） |
| `ready` | 草稿已落盘 | 草稿卡 + 三个按钮；弹窗四项齐全 | ④ / ⑤ / ⑥ |
| `error` | skill 未产出 / 草稿落盘失败 / 写入失败 | 卡片或弹窗内写明**失败原因 + 路径** | `[重试]`；写盘类错误另给「只导出」退路 |
| `stale`（陈旧） | 弹窗打开后目标谱被外部改动 | 弹窗顶部横幅：「目标谱在预览后被改动」 | `[重新预览]`（必做，否则 `[确认更新]` 禁用） |
| `disabled`（禁用） | 未选目标谱 / 未选分节 | `[确认更新]` 置灰 + 一行说明缺什么 | 补齐选择 |
| `done` | 已写入 或 已仅导出 | 草稿卡转「已更新到谱」/「仅导出」，通知出一次 | `[查看谱]`（跳 S5） |
| 窄屏态 | 宽 <1100 | 单列堆叠，弹窗铺满一屏，四要素不折叠 | 同 `ready` |

## 9. 硬约束在 UI 上的呈现

本屏矩阵（README §5）：**C4 ●**、**C10 ●**；C1 / C2 / C3 / C5 / C6 / C7 / C8 / C9 / C11 不涉及。

**C4 沉淀必须人工确认**
- 弹窗内必须同时看见四件东西，且都写死在弹窗里（不是「加个提示」）：① `目标谱（必选）` + 分节；② `变更 diff 预览`（逐段 `+ / ~ / =`）；③ `字数变化`（1,204 → 1,842 字 / +638 字 / +53%）；④ `写入路径（只读展示，界面不可改）` 两行 + 备份路径。
- 按钮文案把闸门写在脸上：卡片上是 `[更新到谱…]`（省略号 = 还没写），弹窗里才是 `[确认更新]`。
- **界面上不存在 AI 自动写入入口**：不注册任何「AI 直接更新到谱」的动作、不在 AI 消息里放写入按钮、不提供「自动沉淀」开关、不提供「总是允许」的玄枢自制开关；草稿卡上的三个按钮全部需要人点（评审验点：全局搜「自动」二字，本屏只出现⑦那句负向声明）。
- 拒绝与绕行是正当路径：`[只导出，不写谱]`、`[丢弃这份草稿]` 与 `[确认更新]` 并列同权重，不作为危险操作藏进「⋯」。

**C10 AI 会动你的东西 → 由 DSH 审批兜底**
- AI 侧唯一的写盘动作是「草稿落盘 `~/.dsh/xuanshu/sediment/…`」——该步在会话里出现 **DSH 审批卡**（原文案：「`xuanshu:sediment` 请求写入 `~/.dsh/xuanshu/sediment/<会话id>.md`」），界面不隐藏、不合并、不预勾选；选项只有 `allowed-once / rejected`。
- **F1 的界面事实**：审批卡是 `conversation.composer` 的顶替 → **只在 `conversation` 面板在屏时可见**。这正是本屏把入口、草稿卡、确认弹窗全部长在会话语境里的原因（D5）；若从 `consult` 门厅发起，必须先 `ctx.layout.selectPanel(null)` 回到会话面板，否则用户「看不到审批卡」。
- 人点 `[确认更新]` 的谱写入不经 AI 工具，属于宿主侧写入，因此**不出现**审批卡；这道闸就是弹窗里的第二次确认本身。
- 界面不提供玄枢自制的「总是允许 / 别再问我 / 记住这个选择」；想长期放行只能去 DSH 的权限预设里改（设置 → 通用 / 权限），本屏只放一句指路文案：「长期放行请在 DSH 权限设置里改，本屏不提供跳过确认」。
- token：确认弹窗与按钮行用 `--xs-constraint-human-gate-fg/-bg`（只用于**人点的控件**的容器）；**审批卡内部不由玄枢上色**（`constraint` 族不定义审批卡 token，token 字典 §9.1 第 4 条）。
