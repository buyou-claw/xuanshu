# S6 · 问事面板

> 归属票：10 ｜ 层级：main 面板 ｜ 槽位：`main`（keyed 槽）key `consult` + `sidebar.panellist`（list 槽）「书房」分区行 id `consult`——键名以 `shared/DSH槽位映射.md` 为准（(需确认)）
> 上游依据：`docs/specs/001-assembly-foundation.md` 用户故事 13–16、19、20 与 Implementation Decisions「问事容器」「安全」；`docs/architecture-v1.md` §5「问事/咨询」「勾选谱」/§6 核心数据流「问事」/§7 数据布局；`.scratch/assembly-foundation/issues/10-consult-closed-loop.md`；`docs/research/dsh-recon.md` §4；`shared/星阙交互规格索引.md` §2.1 / §3.1；`docs/design/ui-v1/README.md` §6.2（H3）/§6.3
> 规格级复用来源：挂载账本（本屏只放入口、状态栏与拦截引导，抽屉本体见 S8）· Best-of-N（本屏只放触发与区块挂点，面板本体见 S9）——均为**规格级复用**
> 本屏不做什么：不自建审批卡（C10，用 DSH 原生）；不把问事挂到任何工作区下；不在这里做谱的编辑（去 S5）；不做临时挂载抽屉与合参面板本体（分别在 S8 / S9）

## 1. 目的与入口

- **从哪进**：S1 自我总览快捷入口「问事」；侧栏 `sidebar.panellist`「书房」分区 → 「问事」（定案 D1）；S4 首次空态的「先问一件事」；S15 管理入口落位。
- **去哪出**：S7 历史回看（面板内子页切换）；S8 临时挂载账本（抽屉）；S9 多 AI 合参面板（会话内区块）；S10 沉淀确认（会话结束入口）；S5 谱管理（勾选区的「管理谱」）。
- **相邻屏**：S1、S4、S5、S7、S8、S9、S10、S15。
- **与工作区的关系（本屏第一句话）**：问事**与工作区并列、不属于任何工作区**——会话没有 cwd 绑定、不出现在任何工作区的会话列表里；开会话不需要先建项目（用户故事 13）。DSH 原 `conversation` 面板与工作区**完全保留、不改**。
- **渲染面（F1，本屏必须先说清）**：`main` key `consult` ≠ `conversation` ⇒ **本面板没有会话绑定**：`conversation.*` 子槽在本面板**不渲染**、`ctx.sidebarRight.mounted === undefined`、`ctx.conversation.send()` 在根上下文会大声失败（证据：`shared/DSH槽位映射.md` §7「S6」+ §6.6 对 S9/S10 的 C10 提醒）。因此本稿把问事拆成**双面协同**（建议定案，需 lead 收口）：
  1. **`consult` 面板（本屏线框）**＝问事**容器**：会话清单 / 勾选谱 / 临时挂载入口 / 历史回看（S7）/ 新问事 / 最近一次会话摘要卡；
  2. **DSH `conversation` 面板**＝对话**本体**：消息流、工具调用、**审批卡（C10 唯一可见处）**、S9 合参区块、S10 沉淀区块。点开 / 新建会话 → 切到 `conversation` 面板并带上该会话（`ctx.layout.selectPanel(null)` 的退路，`shared/DSH槽位映射.md` §8.1 U2）。
  这样做的理由：只有 conversation 面板在屏时，**审批卡才可见**（`conversation.composer` chain 被审批卡顶替）——若把对话本体硬塞进 `consult` 面板，C10 会变成「界面看不见审批」，那是硬约束破防。

## 2. 线框

### 2.1 宽（≥1100，默认）· 会话已开

```
┌ 问事 ────────────────────────────────────────────────────────────────────
│ 问事 · 最近一次会话 #consult-0007（本地）  [历史回看 ▸ S7]    [＋ 新问事]
├───────────────────────────────┬──────────────────────────────────────────
│ ① 本次要用的谱（勾选）         │ ④ 会话本体（在 DSH `conversation` 面板渲染）
│  ── 默认在场 · 不可关 ──       │   点开 / 新建 → 切到 conversation 面板：
│  🔒 底座（八字） 不可关        │    你：帮我看这次转岗的时机
│  🔒 底稿         不可关        │    AI：先读你的谱……（带 DSH 全套工具）
│  ── 基础输入级 base · 默认勾选 │       ⚙ 读文件 pus/软件开发/manifest.md
│  ☑ 人生经历                    │ ⑤ 审批卡（DSH 原生 · 只在 conversation 面板可见）
│  ── 可选输入级 optional        │   ┌ 请求写入 ~/.dsh/xuanshu/pus/… ┐
│  ☐ 软件开发   ☐ 3D 打印        │   │  [允许]  [拒绝]               │
│  [管理谱 ▸ S5]                 │   │  审批由 DSH 决定；玄枢不提供   │
│ ② 本次上下文将含：底座 + 底稿  │   │  「总是允许」之类自制开关      │
│    + 1 个谱 + 1 项挂载         │   └───────────────────────────────┘
│ ③ 临时挂载（工作区 / 工作流）  │ ⑥ 多 AI 合参区块（S9）：候选 2 路并排…
│   工作区 / 工作流不是谱        │    [采用] [合并] [否决]  ← 区块本体在 S9
│   [＋ 临时挂载 ▸ S8]           │
│   已挂：工作区「打印车间」      │
│   挂载 8,420 字 / 预算 60,000  │
├───────────────────────────────┴──────────────────────────────────────────
│ 本面板：勾选谱 / 挂载 / 历史 / 新问事 ｜ 对话本体与审批卡在 conversation 面板
└──────────────────────────────────────────────────────────────────────────
```

**线框说明**：① 勾选谱区——**底座与底稿是锁定行**（无 checkbox、标「默认在场 · 不可关」，C5），其下才是可勾选的 base / optional 两组（base 默认勾选，optional 默认不勾，与 `docs/pu-spec-v1.md` §4 一致）。② 「本次上下文将含」摘要行——把装配结果写成一句人话，勾选或挂载一变就即时更新。③ 临时挂载区——对象**只有工作区 / 工作流**（措辞是「挂载」，不是「勾选」；C6），含常驻一句「工作区 / 工作流不是谱」，入口按钮开 S8 抽屉；状态栏 `挂载 N 字 / 预算 M 字` 常驻（C7 的可见锚点，点击重开 S8 看逐层账本）。④ 会话本体——因 F1，它在 DSH **`conversation` 面板**渲染（消息、工具调用块、S9 区块、S10 区块）；`consult` 面板只显示「最近一次会话摘要卡 + [继续这次问事]」，**不**自己画消息流。⑤ 审批卡——DSH 原生卡片出现在 `conversation` 面板的 composer 位置（审批顶替 composer），这是 C10 唯一可见处；`consult` 面板不发起工具写操作，因此不会出现「审批卡无处显示」的破防场景。⑥ 合参区块位置——S9 的挂载点（区块本体与三动作在 S9，渲染在 `conversation` 面板）。

```
┌ 问事 ────────────────────────────────────────────────────────────────────

│ ① 一次问事 = 勾选谱 → 说事 → （可选）多 AI 合参 → 结束沉淀

└──────────────────────────────────────────────────────────────────────────
```

**线框说明**：① 一句话说清问事是什么、与工作区的关系（C6 的另一处可见落点，是「并列」而非「下属」）。② 三个可执行入口：开新问事（主）、去历史、去管理谱。③ 谱概况行——让人在开会话前知道手上有多少可勾的东西；「谱都非必填」一句避免「必须先建谱」的误读。④ 门厅与正厅的分工（D5）：本面板不渲染消息流、不渲染工具轨迹；点开 / 新建会话 → `ctx.layout.selectPanel(null)` 切到 DSH 原生 conversation 面板。

### 2.3 宽 · 会话内区块落位（示意，渲染在 DSH `conversation` 面板；区块本体见 S8 / S9 / S10）

```
│ 会话流：你 → AI（工具调用块）→ 审批卡(DSH · 顶替 composer) → 合参区块(S9) → …
│ 输入区（DSH 原生 composer）：[说这件事…]（/多模型 命令在此生效）
│ 面板外：consult 面板 = 勾选谱 / [临时挂载 ▸ S8] / 历史 / 新问事
│ 状态栏：挂载 8,420 字 / 预算 60,000 字 · 谱 1 个 · 合参 2 路
```

**线框说明**：一行给实现票看「三件外挂分别在会话流的哪一层」：审批卡顶替 composer（DSH 原生机制）、合参区块占一条 assistant 消息、挂载入口与状态栏在会话面板的输入区上沿（由 `consult` 面板与 `conversation` 面板各自持有的一半拼起来）。状态栏字段与 S8 §2 的 `挂载 N 字 / 预算 M 字` 同源，不另造一套。

## 5. 交互流程

1. **进入面板**：触发 = 侧栏「书房 → 问事」/ S1 快捷入口 → 系统查本地会话清单（按 `meta.xuanshu.kind` 过滤，不调 LLM、不写盘）→ 界面 `empty`（未开会话，见 §2.2）或 `ready`（最近一次会话）。
2. **开新问事**：触发 = `[＋ 开一次问事]` →【副作用】`ctx.sessions.create` 带 `meta.xuanshu = {kind:'consult', pus:[…], mounts:[…]}`（会话落 `~/.dsh/sessions/`，JSONL 事件溯源；**不绑工作区**）→ 界面 `loading` → `ready`（本面板出「勾选谱区 + 锁定行 + 会话摘要卡」）→ **切到 DSH `conversation` 面板**进入对话本体（F1；退路 `ctx.layout.selectPanel(null)`，见 `shared/DSH槽位映射.md` §8.1 U2）。
3. **勾选谱**：触发 = 勾选 / 取消勾选某谱 →【副作用】更新会话 meta `pus`（本地会话记录）→ 界面 `ready`，摘要行变为「…+ N 个谱…」；勾选不触发任何 LLM 调用。
4. **点锁定行**：触发 = 点底座 / 底稿行 → 只弹说明卡（不改变状态、不写盘）；卡内给去 S5（看谱）/ S13（看底稿）的跳转。
5. **说事并发送**：触发 = 在 **`conversation` 面板的原生 composer** 里输入 + 发送 → 系统按「底座 + 底稿 + 勾选谱（manifest 概览 + summary 优先，按需深入）+ 挂载内容（预算裁剪）」装配上下文，带 DSH 全套工具执行 → 界面 `running`（流式 + 可 `[停止]`）；AI 读谱文件由它自己调工具完成（用户故事 16）。
5a. **发送口引导（无源时）**：触发 = 问题指向具体事项、但本次**既无勾选可选谱、也无挂载项**（底座与底稿一直在场，但不构成针对该事项的依据）→ 界面弹引导（结构照 `shared/星阙交互规格索引.md` §2.1「无挂载源时的拦截引导」：标题 + 两条去路 + 单按钮 + **不发送**），文案换成玄枢措辞：「需要先给这一问一点依据 —— ① 在勾选区勾一个谱 ② 临时挂载一个工作区 / 工作流（去 S8）」；末条保留「只带底座 + 底稿问一次」的显式出口（玄枢对上游的加严，见 S9 §2.6 同一判定的另一处落点）。
6. **AI 要动我的东西**：触发 = 工具调用涉及写操作 →【人工确认闸门】**DSH 原生审批卡**出现在会话流（`[允许] / [拒绝]`）→ 界面停在待审批态；玄枢不自建卡片、不提供「总是允许」开关（C10）。
7. **临时挂载**：触发 = `[临时挂载 ▸ S8]`（按钮上带已挂层数角标）→ 抽屉里选工作区 / 工作流 →【副作用】写会话 meta `mounts` → 界面 `ready`，状态栏显示 `挂载 N 字 / 预算 M 字`（超预算时的界面见 S8 两态）。
8. **多 AI 合参**：触发 = 输入 `/多模型 <问题>`（**主命令，照抄上游**；玄枢别名 `/合参`、上游别名 `bestof`）或点会话区「多 AI 合参」按钮 → 进入 S9 区块（2 路并行流、不带工具）→ 人点 `[采用] / [合并] / [否决]`（C9，玄枢「否决」为定案 D4 的自有语义）→ 采用后本会话的后续历史只带采用稿；**合参生成中主发送照常**，界面提示「本次发送会与它并行进行（互不占用发送门闩）」；**H3**：合参是旁路，不改本会话的挂载账本与字数状态。
9. **结束并沉淀**：触发 = 会话头部工具区的 `[导出汇总 ▸ S10]`（**仅当 `meta.xuanshu.kind === 'consult'` 时注册**，与 S10 §1 一致；位置也可在会话收尾条）→【人工确认闸门】S10 的「更新到谱」必须人点确认才写谱（C4）；本屏不写任何谱文件。
10. **回看历史**：触发 = `[历史回看]` → 切 S7 子页（面板内，不新开窗）→ 点开即读。
11. **关会话 / 切走**：会话已落本地（JSONL）；切走不丢记录；若写入失败按 §6「会话写入失败态」处理。

## 6. 关键状态

| 状态 | 什么时候 | 界面是什么样（可执行） |
