# S12 · 工作流创建向导（创建 + 导出 skill）

> 归属票：16 ｜ 层级：**两段式** —— 第一段「门厅」= main 面板（`workflow`），第二段「向导本体」= 会话（DSH 原生 `conversation` 面板承载，D5） ｜ 槽位：`main.workflow`（keyed/root）+ `sidebar.panellist` 行（id `workflow`）+ 会话内 `conversation.input.dock`（list/session，主挂载；当前态区块）——键名以 `shared/DSH槽位映射.md` 为准
> 上游依据：`docs/specs/001-assembly-foundation.md` §Implementation Decisions（用户故事 31）；`docs/architecture-v1.md` §5/§6；`.scratch/assembly-foundation/issues/16-workflow-creation-wizard.md`；`product-definition.md` §七-2 / #12
> 规格级复用来源：无（向导由 `ctx.sessions.create` + `/writing-skills` 组装；会话 UI 沿用 DSH 原样）
> 本屏不做什么：工作流的「测试 / 反向优化 / 复用」细流程**明确不在本屏、不在本票**；不做编排画布；不替人判定跑通与否。

---

## 1. 目的与入口

**它解决什么**：把一件反复要办的事**固化**成一个可复用的 skill——会话里说清要求、用 DSH 的 coding 工具真跑一遍、**你自己判定**跑通了，再点「导出 skill」落到 DSH 的 skill 扫描路径下（不用你指定路径）。

**从哪进**（**两段式**，D5 决定）：
- **第一段 = 门厅（面板）**：S1 自我总览快捷入口 `[工作流]`（票 07 交付）→ 侧栏「工作流」行（main key `workflow`）→ 面板里 `[创建工作流]`。落位见 S15。
- **第二段 = 会话**：点 `[创建工作流]` 后 **进入会话**（`ctx.layout.selectPanel(null)` 切到 DSH 原生 `conversation` 面板，D6）——向导本体（向导条 / 说要求 / 试跑 / 判定条 / 导出）全在会话语境里，因为 `conversation.*` 子槽与**审批卡**都只在 `conversation` 面板渲染（F1）。
- 已在进行中的工作流，从门厅列表点 `[打开会话]` 走同一条路回到会话。

**去哪出**：
- 导出成功 → 产物回到 **DSH 技能中心**（第三方 skill-explorer 覆层，来源显示 `user-dsh`）；门厅列表给 `[在技能中心查看]`。
- 工作流本身可作为问事会话的**临时挂载**对象（跳 S8，用「挂载」措辞）。
- 落盘与拷走说明 → 跳 S15「数据与拷走」。

**相邻屏**：S1（入口）、S8（临时挂载）、S15（入口落位 / C11）、S5（谱——**与工作流互不相干**，本屏用来讲清边界）。

**一句话边界**：向导只负责「把事说清 → 真跑一遍 → 你来判定 → 导出」，**系统不替你判定跑通没有**。

## 2. 线框

【A】向导本体：会话内（宽 ≥1100；**必须落在 DSH 原生 `conversation` 面板**，D5）

```
┌─ 会话「新建工作流」（conversation 面板承载）───────────────────────────────────────
│ ① 向导条（conversation.input.dock · 全宽）   1 说要求 ──▶ 2 试跑 ──▶ 3 你判定并导出
│    当前：2 试跑 · 种子已自动调用 /writing-skills；产物格式沿用 SKILL.md 规范
│
│ ② 说要求（打字 / 加附件给参考）   (输入…)        [+ 附件]
│
│ ③ 试跑区（DSH coding 工具原样：读文件 / 跑命令 / 写文件）
│    ▸ 本轮工具调用 12 次 · 状态 running · [停止]
│    · 试跑产生的文件在本次会话的工作目录里；未导出前不进 skill 管理
│    · 写操作由 DSH 审批卡兜底（审批卡=本会话 composer 的顶替，因此只有在这个面板里才看得见）
│
│ ④ 判定条（人判定，同挂在 conversation.input.dock 的条目里）
│    「跑没跑通由你判定」 —— 本会话不显示通过 / 失败，也不给评分
│    [我认为跑通了 → 导出 skill]     [没跑通 → 继续改要求]     [先放着]
│
│ ⑤ 导出产物说明（点 ④ 左侧按钮后展开）
│    · 产出一个 skill，落点（无需指定路径，只读展示）：~/.dsh/skills/<工作流名>/SKILL.md
│    · 可含 MCP：若流程需要连接器，产物说明里列出连接器名与用途
│    · 导出后出现在 DSH 技能中心（来源：user-dsh），可被后续会话调用
│    · 不在本屏：测试 / 反向优化 / 复用（细流程待定）
└────────────────────────────────────────────────────────────────────────────────────
```
**线框说明（A）**：① 向导条挂在 `conversation.input.dock`（composer 卡片上方的**全宽**条目，list/session、加性、`replaceRisk: none`），是**描述**不是判定器——只显示「现在在哪一步」，不显示成功 / 失败。② 要求输入区沿用 DSH 会话输入（打字 + 附件），不自研输入区。③ 试跑区展示工具调用流水（DSH 原样呈现）+ `[停止]`；**审批卡也在这一屏可见**（它就是本会话 composer 的顶替）。④ **本屏的核心**：判定条上只有人点的按钮与那句「跑没跑通由你判定」；没有任何系统结论。⑤ 点「我认为跑通了」之后才展开产物说明：落点、可含 MCP、去技能中心、范围外事项一次讲清。

【B】门厅面板（main · key `workflow`，宽 ≥1100）

```
┌─ 工作流 ───────────────────────────────────────────────────────────────────────────
│ ① [创建工作流]（= 开会话 + 种子自动调 /writing-skills；点它即 `selectPanel(null)` 进入会话）
│
│ ② 进行中（每条 = 一个会话；本面板只做门厅，不承载会话正文）
│    · 每周整理行业动态        会话 running · 最后活动 21:04     [打开会话]
│    · 报价单生成              会话 ready（等你判定）             [打开会话]
│ ③ 已导出
│    · weekly-industry-digest  skill · 来源 user-dsh · 导出 2026-10-11
│      [在技能中心查看]  [复制产物路径]  [用作临时挂载（跳 S8）]
│
│ ④ 本面板不画：向导条 / 判定条 / 审批卡 / 输入区 —— 它们都在会话里（D5）
│ ⑤ 边界：谱列表里不出现工作流（工作流不是谱）；工作流不是藏（藏永不进 AI）
│ ⑥ 产物与数据都在本地：~/.dsh/skills/ 与 ~/.dsh/sessions/（拷走见 S15）
└────────────────────────────────────────────────────────────────────────────────────
```
**线框说明（B）**：① 门厅唯一的创建入口；点它 → `ctx.layout.selectPanel(null)`（D6：显示当前会话）切到 `conversation` 面板开始向导。② 进行中的工作流 = 会话（每条给 `[打开会话]`，同一条切换路径）。③ 已导出的工作流 = 一个 skill 条目（来源 `user-dsh`）+ 三个下游动作。④ **负向声明**：门厅不承载会话正文，也不画向导 / 判定 / 审批（F1 的直接后果）。⑤ 边界说明（C6）。⑥ C11 指路（一句话 + 跳 S15）。

【C】窄屏（<1100）

```
┌─ 会话 · 新建工作流 ────────
│ ① 1 说要求 ▶ 2 试跑 ▶ 3 判定
│ ② (输入…)         [+ 附件]
│ ③ 工具调用 12 次 · running
│    [停止]
│ ④ 「跑没跑通由你判定」
│    [我判定跑通了 → 导出]
│    [继续改要求]
│ ⑤ 落点：~/.dsh/skills/…
└───────────────────────────
```
**线框说明（C）**：判定条与「跑没跑通由你判定」在窄屏**不折叠**（它不是提示，是规则）；产物说明可折叠成一行 `[产物说明 ▸]`。

## 3. 线框说明

- ① 向导条 — 三态描述（说要求 / 试跑 / 判定并导出）；**无通过失败色、无打分**。
- ② 要求输入 — DSH 会话输入（打字 + 附件）；不自研输入区。
- ③ 试跑区 — DSH coding 工具流水（原样）；`[停止]` 可中断；审批卡同屏可见。
- ④ 判定条 — 全部是人点的动作 + 一句规则文案；`[先放着]` 允许中途离开。
- ⑤ 产物说明 — 落点（只读、无需指定）、可含 MCP、去技能中心、范围外。
- 门厅 ① 创建入口（点它即进会话）；② 进行中（= 会话）；③ 已导出（= skill 条目 + 三动作）；④ 负向声明（不画会话正文 / 向导 / 判定 / 审批）；⑤ 边界；⑥ 本地数据指路。
- 窄屏 — 判定条不折叠；产物说明可折叠。

## 4. 组件树

> **写法规矩（F4/D9）**：一律「**照 X 形状自研**」——不 `require` `@deepseek-ai/dsh-client-ui-primitives` 或任何 Harness Client 包；类名走 `--xs-` 前缀，样式只保留 `--dsw-alias-*` / `--xs-*` token 引用。括号里给的是**形状来源**，不是依赖。

- `XsWorkflowPanel`（自研）— main key `workflow` 的**门厅面板**。
  - `XsWorkflowCreateButton`（自研）— ① 创建入口：`ctx.sessions.create(...)` + `ctx.layout.selectPanel(null)` 进会话。
  - `XsWorkflowRunningList`（自研）— ② 进行中（数据源：`~/.dsh/sessions/` 中 `meta.xuanshu.kind='workflow'` 的会话）。
  - `XsWorkflowExportedList`（自研）— ③ 已导出（数据源：DSH skill 提供者的 `user-dsh` 根，即 `~/.dsh/skills/`）。
    - `XsSkillEntryActions`（自研）— 技能中心 / 复制路径 / 用作临时挂载（跳 S8）。
  - `XsWorkflowNoSessionNote`（自研）— ④ 负向声明（门厅不承载会话正文；列表行形状照 DSH 的列表行，间距字号照 Plugin Manager 页）。
  - `XsWorkflowBoundaryNote`（自研）— ⑤ 边界说明。
  - `XsLocalDataNote`（自研）— ⑥ 本地数据指路（跳 S15）。
- `XsWorkflowWizardDock`（自研）— 会话内 ① 向导条 + ④ 判定条（同挂一个 `conversation.input.dock` 条目，全宽）；`id: xuanshu.workflow-wizard`。
  - `XsJudgeByHumanBar`（自研）— 三个按钮 + 规则文案（**不含**任何系统判定控件）；按钮容器用 `--xs-constraint-human-gate-*`。
  - `XsExportProductNote`（自研）— ⑤ 落点只读 + 可含 MCP + 范围外声明（形状照 DSH 的折叠行）。
- 复用（DSH 原样，玄枢零改动）：会话正文与输入区、工具调用呈现、**审批卡**、附件、技能中心。
- 备选落法：若「这次导出」本身要进会话历史 / 可回放 → `ctx.uiConversation.events.register()` + `conversation.chat.node`（keyed/session，key = definition 的 `kind`）；当前态区块用 `conversation.input.dock` 即可（§6.7 的两条正统路径）。
- **归属检查**：门厅节点落在 `workflow` 面板；会话节点落在 `conversation` 子树；`/writing-skills` 经 `ctx.commands` 与会话创建走宿主 API，不是 UI 组件。

## 5. 交互流程

1. 人点 S1 的 `[工作流]` 或门厅 `[创建工作流]`（触发：按钮）→ **【副作用】** `ctx.sessions.create(id?, { meta: { xuanshu: { kind: 'workflow' } }, seed })`：种子里带一条自动指令调用 `/writing-skills`；随后 `ctx.layout.selectPanel(null)`（D6：显示当前会话）→ 界面：**切到 `conversation` 面板**，向导条停在「1 说要求」，状态 `ready`。（门厅自己**不**画向导，F1）
2. 人打字 / 加附件说要求（触发：输入提交）→ 系统把要求交给会话（`/writing-skills` 已由种子调起）→ 界面：向导条前进到「2 试跑」，状态 `running`。
3. 试跑（触发：Agent 用 DSH coding 工具真跑）→ **【副作用】** 读文件 / 跑命令 / 写文件都发生在**本次会话的工作目录**内；任何写操作按 DSH 规则弹**审批卡**（不自建；它顶替本会话 composer，因此这一屏看得见）→ 界面：试跑区逐条出现工具调用；`[停止]` 可中断。
4. 人读试跑结果，自己判断跑没跑通（触发：人读，**无系统判定**）→ 界面：判定条始终可用，**不出现**「通过 / 失败 / 得分」。
5. 人点 `[我认为跑通了 → 导出 skill]`（触发：按钮，**【人工确认闸门】**）→ **【副作用】** 宿主把本次会话固化的产物写成 `<工作流名>/SKILL.md` 落到 **`~/.dsh/skills/`**（DSH skill 扫描根之一 `user-dsh`，`dsh-skill-filesystem/lib/index.js:171-175`）；若流程含 MCP，产物说明里同时列出所需连接器 → 界面：产物说明展开 → 导出中 `loading` → `done`，通知「已导出 skill：weekly-industry-digest · [在技能中心查看]」。
6. 人点 `[没跑通 → 继续改要求]` → 回到步骤 2，**不留任何产物**（不写 `~/.dsh/skills/`）。
7. 同名冲突（`~/.dsh/skills/<名字>/` 已存在）→ 界面：`error`，给两个正当选项：`[换个名字]` / `[覆盖（先备份旧版）]`；不静默覆盖。
8. 会话中途关掉再回来（触发：从面板 ② 打开会话）→ 界面：向导条恢复到最后一步，产物说明保持折叠；判定仍等人点（状态 `stale`：「上次判定未完成」，但**不代人判定**）。
9. 导出后：skill 出现在 DSH 技能中心（来源 `user-dsh`）；后续会话可调用它；工作流本身可被问事**临时挂载**（S8）。

## 6. 关键状态

| 状态 | 触发条件 | 界面表现 | 可执行动作 |
|---|---|---|---|
| `empty` | 门厅里没有任何工作流 | 空态写「为什么是空的：你还没有创建工作流。工作流 = 说清要求 → 真跑一遍 → 你来判定 → 导出成 skill」+ 主按钮 `[创建工作流]`（点它进会话）+ 次按钮 `[看看工作区（DSH 原样）]` | 创建（进会话）/ 跳工作区 |
| `loading` | 门厅读会话列表与 skill 列表 | 列表骨架（自研，DSH 无 Skeleton 原语） | 无 |
| `running` | 会话正在试跑 | 试跑区流水 + `[停止]`；向导条停在「2 试跑」（**在 conversation 面板内**） | 停止 / 继续等待 |
| `ready` | 试跑有输出，等**人**判定 | 判定条三个按钮可用；**无系统结论** | 判定跑通 / 继续改 / 先放着 |
| `done` | 已导出 skill | 面板 ③ 出现该 skill；会话内产物说明标「已导出」 | 技能中心 / 复制路径 / 挂载 |
| `error` | 会话创建失败 / 种子未调起 `/writing-skills` / 导出失败（权限、同名冲突） | 明写失败原因与落点；同名冲突给 `[换个名字]` / `[覆盖（先备份）]` | 重试 / 改名 / 覆盖 |
| `stale`（陈旧） | 会话中断后重进，判定未完成 | 向导条标注「上次判定未完成」 | 继续判定（不代人判定） |
| 窄屏态 | 宽 <1100 | 判定条不折叠；产物说明可折叠 | 同 `ready` |

| 临时挂载 | 会话 meta `mounts`（S8 的挂载抽屉） | 工作流可被挂载；**不是**谱（C6） |

## 9. 硬约束在 UI 上的呈现

本屏矩阵（README §5）：**C8 ●**、**C6 ●**、**C10 ○**、**C11 ○**；其余不涉及。

**C8 是否跑通由人判定**
- 界面上**没有**系统的「通过 / 失败」判定：不显示 ✅ / ❌、不给分、不给「测试通过」Tag、不自动进入导出。
- 判定条只有人点的三个动作，旁边逐字写着「跑没跑通由你判定 —— 本会话不显示通过 / 失败，也不给评分」；**闸门呈现是人点的控件**（按钮行容器用 `--xs-constraint-human-gate-fg/-bg`），不用一句提示文案代替。
- 导出按钮文案把人来意写进按钮里：`[我认为跑通了 → 导出 skill]`（主语是「我」）。
- 中断后重进**不代人判定**：只标 `stale`「上次判定未完成」，按钮照旧等人点。

**C6 谱与工作区 / 工作流并列独立**
- 谱列表里**不出现**工作流（S5 侧的同一条约束，本屏在门厅 ⑤ 里正向声明）；工作流的容器是会话与门厅面板，不生成谱条目。
- 工作流进入问事上下文的唯一通道是**临时挂载**：门厅 ③ 的动作写作「用作临时挂载（跳 S8）」，用「挂载」措辞，**不用「勾选」**；挂载抽屉里只列工作区 / 工作流（S8 负责）。
- 边界一行成对写：工作流不是谱（不进谱列表）、工作流不是藏（藏永不进 AI）。
- token：C6 由 `level` 族的 `nonpu` + 文字标签承载，`constraint` 族不参与（token 字典 §12 说明）。

**C10 AI 会动你的东西 → 由 DSH 审批兜底（○ 涉及处）**
- 试跑阶段任何写操作按 DSH 规则走**审批卡**（原样呈现，不合并、不隐藏、不预勾选；两选一，无「总是允许」）；界面不提供玄枢自制的「总是允许 / 别再问我」，长期放行只在 DSH 权限预设里改。
- **F1 的界面事实**：审批卡只在 `conversation` 面板可见 —— 向导本身就在会话里，所以天然可见；这也正是**门厅不画向导条与判定条**的原因（否则用户会以为「点了没反应」）。
- 导出 skill 的写入由**人点按钮**触发并在产物说明里明示落点，因此不以审批卡代替人的确认。

**C11 一切数据本地、可整体拷走（○ 涉及处）**
- 产物落 `~/.dsh/skills/`（本地目录），会话落 `~/.dsh/sessions/`（本地 JSONL）；门厅 ⑥ 写明这两条并跳 S15 的「数据与拷走」内页（含路径只读展示与整体拷走说明）。

## 11. 验收自检

对照 `.scratch/assembly-foundation/issues/16-workflow-creation-wizard.md` 的三条 checklist：

| # | checklist | 怎么验 |
|---|---|---|
| 1 | 自我总览 → 「创建工作流」入口 → 新会话 seed 自动调 `/writing-skills` | 从 S1 点 `[工作流]`（或门厅 `[创建工作流]`）→ 断言新会话被创建且 `meta.xuanshu.kind='workflow'`；断言切换是 `ctx.layout.selectPanel(null)`（回到 `conversation` 面板）而不是新开 key；断言会话首轮出现 `/writing-skills` 的调用痕迹（种子生效）；断言该会话里**不**出现系统的通过 / 失败判定（界面搜「通过」只应命中那句规则文案） |
| 2 | 会话带 coding 工具可试跑，人判定跑通 | 在会话里给一段要求 → 断言试跑期间出现工具调用（读 / 写 / 命令）且写操作弹出 DSH 审批卡（**在这一屏可见** —— 审批卡是本会话 composer 的顶替）；断言判定条三个按钮在试跑结束后可用、`[我认为跑通了 → 导出 skill]` 只在人点后才有后续动作；断言在门厅面板（`workflow` key）下**看不到**向导条与判定条（F1 的正向验证） |
| 3 | 「导出 skill」落 DSH skill 扫描路径，产物回到 skill 管理 | 点导出 → 断言 `~/.dsh/skills/<工作流名>/SKILL.md` 已生成（`dsh-skill-filesystem/lib/index.js:171-175` 的 `user-dsh` 根）；断言技能中心里出现该 skill（来源 `user-dsh`）；断言同名冲突路径给出「换个名字 / 覆盖（先备份）」，无静默覆盖 |

补充自检（README §3.4 / §3.6）：空 / 加载 / 错误三态齐备，空态可执行（给按钮 + 指向工作区 / S15）；`running` / `done` / `stale` 追加态已写；「测试 / 反向优化 / 复用」在 ⑤ 与 §1 两处明写为范围外；线框每行 ≤100 字符；无视觉精修取值（不含配色 / 像素 / 字号）、无代码、无绝对路径。
