## 1. 目的与入口

- **从哪进**：S6 问事面板头部 `[历史回看]`（面板内子页切换，不新开窗）；S6 落地态 `[看看问事历史 ▸ S7]`；S10 沉淀页的「这次会话 ▸ 回看」。
- **去哪出**：S6（切回当前会话）；S10（某条历史里的「沉淀本次」）；本地文件（导出记录）。
- **相邻屏**：S6（宿主面板）、S9（合参轮次在回看里的呈现口径）、S10（沉淀入口）、S15（数据目录说明）。
- **形态二选一（本屏定案）**：**选「S6 面板内的子页」**，不新增独立 main key。理由：① README §2 已把它登记为「面板内子页」，`shared/DSH槽位映射.md` §7「S7」独立复核后给出同一结论；② 历史与当前会话共享同一份「会话清单 + 勾选谱 + 挂载」状态，独立 key 会多一次面板生命周期与状态同步、并让侧栏「书房」区多出一行与「问事」语义重叠的入口；③ 备选的「右列页」（`ctx.sidebarRight.openTab`）需要「在屏会话」，而在 `consult` 面板下 `ctx.sidebarRight.mounted === undefined` ⇒ `openTab` 会**大声失败**（该表 §7「S7」风险），因此不走右列。**代价**：不能在两个窗口并排看历史与当前会话——首版接受（记录为偏离）。阅读器里给 `[继续这次问事 ▸]` 缓解这一点（切回 conversation 面板，D6）。

**线框说明**：① 按日期分组的行——每行给「会话 id / 标题（首句生成的短标题）/ 时间 / 轮数 / 勾选谱数 / 挂载项数 / 是否有合参」，让人一眼分辨哪次是哪次。② 分组头随日期推进（今天 → 更早）。③ 底部常驻一行说明数据形态（本地 JSONL）与搜索边界（只搜标题与首句，避免用「搜索」暗示可全文检索——全文检索是 `(需确认)` 的后置能力，不进首版）。工具条左侧 `[← 回到当前会话]` 是子页切换（不是路由跳转），右侧 `[导出选中] / [删除]` 为对选中行的批量动作（无选中时禁用）。

## 5. 交互流程

1. **切到历史**：触发 = S6 头部 `[历史回看]` → 系统读本地会话清单与各会话首条消息（生成短标题；**不调 LLM**、不写盘）→ 界面 `loading` → `ready`（按日期分组倒序）或 `empty`。
2. **搜索 / 筛选**：触发 = 关键词或范围 → 本机过滤（标题 + 首句 + 日期范围）→ 界面 `ready`；无命中 → 筛选空态（§2.3 ②）。
3. **点开即读**：触发 = 点某行 → 系统读该会话 JSONL（事件回放为消息流）→ 界面 `loading` → `ready`（阅读器，只读）；合参轮次按「只带采用稿」渲染（§2.2 ④），**否决轮次不带任何候选正文**（D4）。
4. **导出记录**：触发 = `[导出记录]` / `[导出选中]` →【副作用】写一份**原文** MD 到本地数据目录（`~/.dsh/xuanshu/exports/consult-<id>.md`，(需确认) 目录口径），界面弹一次落盘提示（显示目标路径 + `[打开所在目录]`）；导出**不改任何谱**（与 S10 的「导出汇总」是两件事）。
5. **沉淀本次**：触发 = `[沉淀本次 ▸ S10]` →【人工确认闸门】跳到 S10；写谱只在 S10 的人点确认里发生（C4），本屏不写谱。
6. **删除一条 / 批量删除**：触发 = `[删除]` →【人工确认闸门】二次确认弹窗，文案写清三件事：① 删除的是**本地会话记录文件**，删除后不可恢复；② **已沉淀到谱的内容不会回滚**（谱是独立文件）；③ 合参落选候选会随之消失 → 确认后【副作用】删除对应会话文件 → 列表 `ready`（条数更新）。
7. **读取失败**：触发 = 某会话 JSONL 损坏 / 解码失败 → 该行标 `error` + `[查看原始文件]` + `[删除此条]`，其余行照常。

|---|---|---|
