## 1. 目的与入口

**目的**：把玄枢唯一的必填项立起来——填一次出生信息 → 出盘 → 落底座谱 → 点亮命盘卡，之后不再重复录入。这是「底座立不立得起来」的唯一入口。

**从哪进**

| 入口 | 形态 |
|---|---|
| S4 / S1 命盘卡空态 `[开始填写出生信息]` | 打开向导本体（`overview` 面板的 `onboarding` 子状态），默认从第 1 步开始 |
| 首启空白会话的 hero 引导 | `conversation.hero` 子槽上一句引导 + 一个按钮，点击同样进向导本体 |
| S2 命盘卡详情底部 `[重新录制出生信息]` | 【人工确认闸门】二次确认后进向导，**预填现值**（第 1 步起，五步都带旧值） |

**去哪出**

- 第 5 步 `[确认并出盘]` 成功 → 落底座谱 → 自动回到 **S1 自我总览**，命盘卡点亮（`empty → ready`）；
- 任意步 `[取消向导]` → 回 **S4 / S1**（未落任何盘，**无副作用**）；
- 出盘失败 / 澄清闸拦截 → 留在向导内（见 §6），不静默退出。

**相邻屏**：S4（首次空态 = 本屏的入口页）；S1（出口页）；S2（预填来源）；S15（底座未就绪时的排查落点）。

## 3. 线框说明

> 线框内一律用 ASCII 符号（`-` 代替 `·`、`->` 代替箭头、`(o)/( )` 表示单选、`...` 代替省略号），以便 diff 与终端阅读；正式文案与标点以各节散文为准。

### 3.1 第 1 步（§2.1）

- ① **日期字段**：单击开选择器；默认公历，农历换算由底座做（玄枢不算历）。
- ② **时间字段**：显示 `YYYY-MM-DD HH:mm:ss` + 固定小字**「当地时间」**（防歧义的关键：用户填的是钟表时间，不是真太阳时）；无值占位 `---- -- -- --:--:--`。三种编辑方式并存：单击 popover / **双击就地键入 14 位数字**（`19900101040000` 输满即提交、回车提交、Esc 取消、提交后时区沿用）/ 下方内联微调条。
- ③ **内联微调条**：`[-] [粒度] [+] [此刻] [确定]`，粒度档 = **年 / 月 / 天 / 小时 / 四分钟**——「四分钟」= 1° 经度时差，与真太阳时的换算粒度同源，**不要改写成「加减分秒」**。
- ④ **提交节奏**：拖动 / 微调中只做静默预取（240ms 防抖、不出盘），落定（弹窗确定 / 14 位提交 / 微调落定）才走正式取数——线框上表现为**没有闪烁的 loading**。

### 3.2 第 2 步（§2.2）——双通道与「地图选点」的取舍

- ① **通道 A 离线城市库（保留）**：小库即时可用 + 大库懒加载；输入即时回显、180ms 防抖后过滤；无关键词时只列常用城市；无匹配时的引导文案玄枢改为**「无匹配城市，可改用手输经纬度」**（上游原话是引导去地图，地图在玄枢不存在）。
- ② **通道 B 手输经纬度（保留）**：标题写明「GPS 十进制」，**经度在前、纬度在后**，两框都支持回车直接应用，非法值忽略不回填。
- ③ **地名与坐标同框**：显示「地名 + 经度·纬度（度分串）」；手输经纬（无可读地名）时**据实显示「未命名地点」，不许留旧地名**——这属于防脏状态。
- ④ **地图选点：玄枢 v1 明确不做**（`shared/星阙交互规格索引.md` **索引 D2**）。理由三条：**(a)** 地图要联网与地图密钥，与 C11「一切数据本地」和铁律「不联网取外部资讯」相抵；**(b)** 离线城市库 + 手输经纬已覆盖「城市 / 区县」与「海外 / 小地名」两端，地图选点的增量价值最低；**(c)** 无地图即无 GCJ-02 坐标，玄枢只产出 `lon`/`lat`（度分串）+ `gpsLon`/`gpsLat`（十进制）**一套坐标**，少一类「两套值不一致」的 bug（**索引 D3**）。保留上游「任一通道失败不阻断选点」的精神：城市库加载失败静默兜底只用小库，仍可手输。
- ⑤ **选点联动的核心语义**：选新地点 → **先按新坐标自动校正时区（仅当本次没手改过时区）** → **保留钟面时刻、只换时区标签、不移位时间**；随后一次性写入 `lon`/`lat`/`gpsLon`/`gpsLat`/地名/`date`/`time`/`ad`/`zone`。

### 3.3 第 3 步（§2.3）

- ① **自动推导**：经纬 + 日期 → `{zone, offset, dst, geoZone, advisory}`；**自动含夏令时**；中国大陆按统一北京时间口径处理（只归并 IANA 名 `Asia/Urumqi → Asia/Shanghai`，**不写死偏移**；新疆的「官方 +08:00 · 当地惯用 +06:00」提示保留，但**不给「按当地」一键切换**——玄枢 v1 让用户自己在偏移表里选）。
- ② **手动覆盖**：固定 UTC 偏移表 28 档；手改后置 `zoneOverride`；**`[自动]` 按钮只在已手改时可用**（未手改时置灰，因为它没有可清除的东西）。
- ③ **口径边界**：时区只负责「钟表时间 → UTC 的偏移归一」；**真太阳时（经度 + 均时差）由 horosa 引擎按 `timeAlg` 换算，录入层不换算**——手动覆盖时区之后仍然如此。

### 3.4 第 4 步（§2.4）

- ① **时间算法三档**：`0 真太阳时`（默认档，**玄枢透传时省略该键**，不显式写 0）、`1 直接时间`、`3 平太阳时`；`2 春分定卯时`上游自身未实现，**界面上不出现**（不给点了没反应的开关）。
- ② **性别三档**：`未知（按男排）` / `女` / `男`——大运顺逆与小运需要性别择一，故「未知」的后果必须写在界面上。
- ③ **其余旋钮一律不给**：长生 / 神煞查法 / 晚子时四态 / 命宫起法 / 月律分野 / 南半球月令 / 起运精度 / 藏干版本 / 生肖归属 / 断命流派 / 显示区（共 10 键 + 两组）——**全部省略 = 由引擎缺省决定**，界面不出现。理由：v1 只透传出生信息 9 键 + `timeAlg`，口径越干净越可复现；且晚子时两开关的四态组合没法用一句话讲清，宁可不给。
- ④ **换算位置**：写在右栏，防用户在向导里找「真太阳时修正」开关（**没有这个开关，也不需要有**）。

### 3.5 第 5 步（§2.5）

- ① **确认表**：五行（出生时间 / 出生地 / 时区 / 时间算法 / 性别）逐行可回跳修改。
- ② **不确定项**：把「只知道大概」显式化，写进 `clarification_notes`（随出盘请求一起给底座），而不是逼用户填一个假精确值。
- ③ **澄清闸**：勾选「以上信息我已核对」是**出盘按钮的解锁条件**；底座若回问，就地展开（§2.7）并回到本步。
- ④ **状态位**：右下角固定显示「可出盘 / 缺经纬度（禁用）」，让禁用态**在点之前就能看见**。

### 3.6 附图（§2.6 / §2.7）

- §2.6 的禁用态是**索引 D6（缺经纬度禁止出盘）的界面本体**：宁可不出盘，也不产出一个「静默退化成钟表口径」的盘。
- §2.7 的澄清闸拦截**不落谱、不点亮命盘卡**；用户回答后重新出盘，走同一条调用路径。

## 5. 交互流程

1. **进入向导**（S4/S1 按钮，或 S2 的「重新录制」二次确认后带旧值进入）→ 界面状态 `draft`，第 1 步；**无副作用**。
2. **第 1 步改任意项** → 走同一条路：把「本字段 + `date` + `time` + `ad` + `zone`」**五键全量重锚** → 未确认只做本地预取（240ms 防抖、silent），落定才正式重算 → 界面在 `draft → ready` 之间切换；**本步不出盘、不写盘**。
3. **第 2 步选地点** → 通道 A（离线城市库）或通道 B（手输经纬）→ 写入 `lon`/`lat`（度分串）+ `gpsLon`/`gpsLat`（十进制）+ 地名（无名时「未命名地点」）→ **保留钟面时刻、按新坐标校正时区（仅当未手改时区）** → 第 3 步的时区标记进入 `stale`（「地点变了，时区待重算」）→ 自动重算后回 `ready`。
4. **第 2 步打开地点弹窗** → 弹窗每次打开自增序号强制重挂载 → **清掉上一轮的临时时区覆盖**（H1）→ 界面回到「自动推导」结果；**无副作用**。
5. **第 3 步手动覆盖时区** → 置 `zoneOverride` → `[自动]` 变可用；点 `[自动]` → 清除覆盖、回到按地点 + 日期自动推断。
6. **第 4 步选档** → 时间算法（默认档 = **省略该键**）与性别写进草稿；**无副作用**。
7. **第 5 步核对** → 勾选不确定项（写入 `clarification_notes`）→ 勾选 `[x] 以上信息我已核对` → **【人工确认闸门】** → `[确认并出盘]` 解锁（缺经纬度时保持禁用 + §2.6 文案）。
8. **出盘** → **【副作用】**调 `mcp__horosa__bazi_birth`，带 `agent_confirmed_settings:true` + `clarification_notes`；`timeAlg`：默认档**省略**，其它档透传 `1` / `3`；请求序号自增以**丢弃过期回包**；界面 `loading`（按钮转进行中、表单只读）→ 收到 envelope `{ok,tool,version,data,summary,warnings,error}`（含 `technique_card`）→ **一次落定、同帧全亮** → `ready`。
9. **澄清闸拦截** → envelope 带回问（warnings / clarification）→ **就地展开**「底座需要你确认」（§2.7）→ 用户回答后**重新出盘**（回到第 5 步 → 第 8 步）；拦截期间**不落谱、不点亮命盘卡**。
10. **落底座谱** → **【副作用】**写 `~/.dsh/xuanshu/pus/_base/bazi.md`：frontmatter（`spec: pu/1` / `name: 底座八字` / `level: base` / `source: manual` / `updated_at`）+ 八字要点快照 + 本次口径（`timeAlg` 实际档位、经纬度、时区、性别）；这是本屏**唯一的写盘动作**。
11. **点亮命盘卡** → 回 S1，命盘卡 `empty → ready`（读第 10 步写的快照，不重新出盘）。
12. **再录制**（S2 底部）→ **【人工确认闸门】**二次确认弹窗（写明「将重录出生信息并重新出盘；旧快照会被新结果替换；底稿会随之刷新」）→ 回到第 1 步并预填现值；成功后旧快照被原子替换。
13. **C10 兜底** → 若落谱等写操作触发 DSH 审批，界面照常弹出 DSH 审批卡，**不隐藏、不提供「总是允许」的玄枢自制开关**。

## 6. 关键状态

| 状态 | 本屏表现 |
|---|---|
| `empty` | 不适用「无数据空态」（向导本身就是空表单）；**未开始态** = 第 1 步空表单 + 时间占位 `---- -- -- --:--:--` + `[确认并出盘]` 不可达（提示「先填出生信息」） |
| `loading` | 仅**出盘**与**时区重算**两处：出盘时 `[确认并出盘]` 转进行中、表单只读、步骤条不动；时区重算时第 3 步结果区显示「重算中」；**步骤切换本身不 loading**；过期回包一律丢弃（请求序号） |
| `error` | 分五种，各自可执行：**(a) 底座未就绪**（`mcp__horosa__*` 不可用）→ 「底座没起来」+ `[重试]` + `[去排查 -> S15]`；**(b) 缺经纬度** → 出盘禁用 + §2.6 文案 + 两个修复入口；**(c) 澄清闸拦截** → §2.7 就地回问 + 回答后重出盘；**(d) 出盘失败**（envelope `ok:false` 或 `error`）→ 显示底座 `error` 原文 + `[重试]` + `[改出生信息]`；**(e) 落谱失败** → 「八字算出来了，但底座谱没写进去」+ `[重试写盘]` + `[看数据目录 -> S15]`（**不点亮命盘卡**，避免出现「有盘无谱」的半成品） |

**追加态**

- **禁用态**：`[确认并出盘]`（缺经纬度 / 未勾选核对）；`[自动]`（未手改时区时）；`2 春分定卯时`档**不出现**而不是置灰。
- **防脏状态（H1，README §6.2）**：地点弹窗**每次重开必须复位临时时区覆盖**（自增序号强制重挂载），否则上一轮在弹窗里手改的 +06:00 会悄悄带到这一次录入；同理「手输经纬无名 → 显示未命名地点，不留旧地名」；离开向导再进入 → 回第 1 步、不带上一次未出盘的草稿（草稿只在本次向导会话内）。
- `stale`（陈旧）：第 2 步改了地点之后、时区尚未落定期间，第 3 步结果标 `stale`（「地点变了，时区待重算」）；重算落定即回 `ready`。
- **中断 / 并发态**：出盘进行中关掉向导 → 界面重进时显示「上次出盘没跑完」+ `[重试]`（宿主侧调用语义 **(需确认)**：是继续等待还是视为失败，由实现票定并在本稿回写）；出盘期间禁止再次点击（单飞）。
- **只读态**：出盘成功后本屏不再有编辑入口（要改走 S2 的「重新录制出生信息」二次确认路径）。
- **窄屏态**：单列 + 主按钮吸底（§2.1–§2.5 的窄屏线框）；确认表 5 行等高。
