## 1. 目的与入口

**它解决什么**：让玄枢**主动找你**——每天到点给一次「当日运势 + 注意事项」，只基于**底座 + 确切的时间基准**（当天日期 / 时刻，供大运 / 流年 / 流日推算）。这是 local-first 的主动触达，不是资讯订阅。

**从哪进**：
- S1 自我总览「日课卡」→ 卡内展示当日摘要，点开进详情（本屏 A）。
- 设置 ▸ **数据与拷走**内**一行指路文字**「定时任务：见左侧『自动化任务』面板」→ 点该指路 → 本屏 B（DSH `schedules` 面板：玄枢自带任务 + 自定义任务管理）。**玄枢不新增设置页、不另造第二个定时任务管理面**（README §6.5 / §6.6 R2；本屏 §1、§4、§5 步骤 5 同此口径）。

**去哪出**：
- 日课详情里的 `[查看投递会话]` → 玄枢内部**系统会话**（DSH 会话列表里以「玄枢 · 系统」呈现，按会话目录归属）。
- `[打开自动化任务面板]` → **DSH 原样的 `schedules` 面板**（侧栏「自动化任务」行；README §6.5 定案：玄枢不另造第二个定时任务管理面）。
- 技法依据 → 折叠展开的**技法依据卡**（由底座 horosa 给出，来源可溯）。

**相邻屏**：S1（日课卡宿主）、S3（底座未就绪时跳八字向导）、S13（底稿刷新任务同在本屏 B 管理）、S15（入口落位）。

**一句话边界**：日课不是「资讯推送」——它只读底座、只看时间，**不联网取任何外部资讯**。

## 2. 线框

【A】日课卡详情（S1 日课卡 → 详情；面板内区块 / 抽屉）

```
┌─ 日课 · 2026-10-11（周日） ────────────────────────────────────────────────────────
│ ① 时间基准（确切，生成时使用）：2026-10-11 07:30 · Asia/Shanghai（+08:00）· 本机时钟
│    · 不联网取外部资讯：本次内容只用底座 + 上面的时间基准
│ ② 当日运势（底座推运：流年 / 流日）
│    一句话总览：今日宜把长期事项往前推一步；午后容易分心。
│    ▸ 依据（技法依据卡：来源技法 + 盘面参数 + 生成时刻）        ← 折叠
│ ③ 注意事项（最多 3 条）
│    1. 谈条件类的事放在上午，措辞按书面来。
│    2. 15:00 后避免临时改长期承诺。
│    3. 留一段独处时间复盘本周。
│ ④ [重新生成（今天）]  [查看投递会话]  [改时刻]  [打开自动化任务面板]   ⑤ 状态 done · 生成于 07:30
└────────────────────────────────────────────────────────────────────────────────────
```
**线框说明（A）**：① 时间基准是本屏的**硬要求**：把生成时用的日期、时刻、时区（IANA 名）与来源（本机时钟）都摆出来，并紧跟一句「不联网」。② 当日运势给一句话总览；`▸ 依据` 折叠出技法依据卡（可溯源，不是黑匣子结论）。③ 注意事项最多 3 条（版面与可读性的取舍，超过即截断并在依据里说明）。④ 四个动作：`[重新生成（今天）]`（人主动重算一次，覆盖当日卡）、`[查看投递会话]`、`[改时刻]`（改播种出去的那条日课任务）、`[打开自动化任务面板]`（跳 DSH 面板）。⑤ 状态与生成时刻。

【B】定时任务管理 = **复用 DSH 的 `schedules` 面板**（玄枢不另造，README §6.5）

```
┌─ DSH 自动化任务面板（玄枢零改动复用；侧栏行 order 10）─────────────────────────────
│ ① 玄枢播种进来的任务（在该面板里就是普通任务：可见、可改、可停用）
│    · 日课        daily  07:30  Asia/Shanghai   下次 2026-10-12 07:30
│      内容＝底座 + 时间基准（不联网）· 投递：玄枢系统会话
│    · 底稿刷新    daily  07:15  Asia/Shanghai   下次 2026-10-12 07:15
│      内容＝三源提炼（见 S13）· 投递：玄枢系统会话      （默认时刻 (需确认)）
│ ② 用户自定义任务（DSH 原生能力，玄枢不插手）
│    · 每周复盘    weekly 周一 09:00  Asia/Shanghai   下次 2026-10-13 09:00
│    · 读一段资料  every（自上次触发起算）             下次 2026-10-12 10:20
│ ③ 玄枢侧入口只有两个：日课详情的 [改时刻]（直调 ctx.schedule.update）
│    与 [打开自动化任务面板]（ctx.layout.selectPanel('schedules')）
│    —— 玄枢不提供第二个任务管理页、不新增设置内页、不自建面板（避免双入口）
└────────────────────────────────────────────────────────────────────────────────────
```
**线框说明（B）**：① 玄枢只**播种**两条默认任务（日课、底稿刷新）进 `ctx.schedule`；它们在该面板里以普通任务出现——用户能看见、能改时刻、能停用（这是「默认自带」与「用户可自定义」两条要求的同一张面孔）。② 自定义任务直接用 DSH 原生能力（daily / weekly / every / cron 四类规则），玄枢不包装。③ 玄枢侧只留两个**入口**（`[改时刻]` 写 `ctx.schedule.update`；`[打开自动化任务面板]` 切面板），**不新增** `settings.section` 定时任务页。

【C】投递表现（系统会话 + 日课卡）

```
┌─ 投递链路 ────────────────────────────────────────────────────────────────────────

│ 底座未就绪 ⑦ 日课卡显示「底座未就绪，日课无法生成」+ [去完成出生信息（S3）]
```

**线框说明（C）**：① 任务在 `ctx.schedule` 里登记为 daily（默认 07:30，时区 IANA）并绑定玄枢系统会话投递。② 生成只做两件事：读底座、取当前时刻（**不发起任何联网请求**）。③④ 落盘 + 投递。⑤ 日课卡在到点后自更新，并给出「查看投递会话」的入口（投递这件事在界面上是**可见、可点**的，不是静默后台）。⑥ 未到点或生成失败时**显示上一份并标陈旧**，不给空白。⑦ 底座未就绪是可执行空态，指向 S3。

## 3. 线框说明

- ① 时间基准 — 日期 + 时刻 + IANA 时区 + 来源（本机时钟）+ 「不联网」；生成时即固定，事后不追改。
- ② 当日运势 — 一句话总览 + 可折叠的技法依据卡（来源可溯）。
- ③ 注意事项 — 最多 3 条，分条编号。
- ④ 动作 — 重新生成（今天）/ 查看投递会话 / `[打开自动化任务面板]`（跳 DSH `schedules` 面板）；**本屏不提供「设置」入口**（README §6.6 R2：只允许在设置 ▸ 数据与拷走内留一行指路文字）。
- ⑤ 状态 — `done` + 生成时刻；未到点 / 失败时为 `stale`。
- B ① 玄枢播种的两条任务（日课 / 底稿刷新）在 DSH `schedules` 面板里以普通任务出现：可见、可改时刻、可停用。
- B ② 自定义任务走 DSH 原生能力（四类规则），玄枢不包装、不另造页。
- B ③ 玄枢侧入口只有两个：日课详情的 `[改时刻]` 与 `[打开自动化任务面板]`；不新增设置内页、不自建面板。
- C 投递链路：触发 → 生成（读底座 + 时间）→ 落盘 → 投递 → 日课卡更新；未到点显示上一份并标陈旧。

## 5. 交互流程

1. 到点触发（触发：`ctx.schedule` 的 daily 任务，默认 07:30，`timeZone` 为 IANA 名）→ **【副作用】** 启动内置 skill `xuanshu:rikke`：读底座谱 `~/.dsh/xuanshu/pus/_base/bazi.md` + 取当前时刻 → 调 horosa 推运（本地 MCP，**无联网请求**）→ 写当日卡 → **【副作用】** 投递到玄枢系统会话（`ctx.sessions.create(id?, {meta:{xuanshu:{kind:'system'}}})` 建一次，之后按会话 id 投递）→ 界面：S1 日课卡换成当日内容，顶部一行「今日日课已到（07:30）· [查看投递会话]」。
2. 人点日课卡进详情（触发：点击）→ 界面：A 区渲染（① 时间基准先出，正文随后）→ `ready`。
3. 人点 `[重新生成（今天）]`（触发：按钮，**【人工确认闸门】** 覆盖当日卡需一次轻确认：「将覆盖今天的日课，继续？」）→ **【副作用】** 重跑步骤 1（同一时间基准 = 当前时刻；落盘覆盖当日卡）→ 界面：`running` → `done`，① 的时间基准更新为新时刻并**保留旧时刻的记录**（写明「本卡由 07:30 生成，09:12 重新生成」）。
4. 人点 `[查看投递会话]`（触发：按钮）→ **【副作用】** `ctx.uiWorkspace.openSession(系统会话 id)`（**在 `conversation` 面板里打开**；若当前在 `overview` / 其他面板则等同 D5/D6 的「回到会话语境」）→ 界面：可见当日投递内容与生成过程（含工具调用与技法依据；若那次写入有待处理审批，审批卡就在这一屏）。
5. 人点 `[打开自动化任务面板]`（触发：按钮）→ **【副作用】** `ctx.layout.selectPanel('schedules')` → 界面：切到 DSH 的自动化任务面板；玄枢播种的两条任务就在列表里（普通任务形态，可见 / 可改 / 可停用）。
6. 人在日课详情里点 `[改时刻]`（触发：内联编辑 + 保存，**【人工确认闸门】**）→ **【副作用】** `ctx.schedule.update` 改那条日课任务（`time` / `timeZone`）→ 界面：详情回显新时刻；DSH 面板里的「下次触发」随之变化。
7. 人停用日课（触发：在 DSH 面板里停用，DSH 原样交互）→ **【副作用】** 任务转停用 → 界面：面板条目转停用态；玄枢侧日课卡转 `disabled`：「日课已停用」+ `[去启用]`（跳 DSH 面板）。
8. 人新增自定义任务（触发：在 DSH 面板里新增，DSH 原生表单）→ **【副作用】** `ctx.schedule.create(系统会话 id, {…})` → 界面：到点后按同一链路生成内容并投递；玄枢侧**不出现第二份列表**。
9. 生成失败（horosa 未就绪 / 推运报错）→ 界面：日课卡 `error`，写明失败原因，给 `[重试]` 与 `[检查底座（跳 S3）]`；**当日卡不写半成品**（原子写入，失败即保留上一份）。

## 6. 关键状态

| 状态 | 触发条件 | 界面表现 | 可执行动作 |
|---|---|---|---|
| `empty` | 今天还没到点、且没有历史当日卡（首次安装当天） | 空态写「为什么是空的：日课在每天 07:30 生成；今天还没到点，也没有可显示的上一份」+ 主按钮 `[立即生成（今天）]` + 次按钮 `[改时刻]` + 「底座未就绪」时改为主按钮 `[去完成出生信息（S3）]` | 立即生成 / 改时刻 / 跳 S3 |
| `loading` | 到点生成中 / 手动生成中 | 日课卡骨架屏（卡级，**自研**骨架，不整页 loading） | 无 |
| `ready` | 当日卡已生成 | ① 时间基准 + ② 运势 + ③ 注意事项 + ⑤ 状态 `done` | 重新生成 / 看投递会话 / 改时刻 / 打开自动化任务面板 |
| `error` | horosa 未就绪、推运失败、落盘失败、有待处理审批 | 写明失败原因与**没写成的文件**；保留上一份内容（若有）；待审批时给「去系统会话处理」 | 重试 / 跳 S3 / 去系统会话 |
| `stale`（陈旧） | 未到点或当天生成失败，界面显示的是上一份 | 卡片标「陈旧（生成于 <日期> <时刻>）」+ `[立即生成（今天）]` | 立即生成 |
| `disabled`（禁用） | 日课任务被停用（在 DSH 面板里停的） | 卡片标「日课已停用」+ `[去启用]`（跳 DSH 自动化任务面板） | 去启用 |
| 窄屏态 | 宽 <1100 | 单列；时间基准与「不联网」不折叠 | 同 `ready` |

## 9. 硬约束在 UI 上的呈现

本屏矩阵（README §5）：**C10 ○**；其余不涉及。

**C10 AI 会动你的东西 → 由 DSH 审批兜底（○ 涉及处）**
- 日课生成发生在**玄枢系统会话**里，写盘若触发审批，**审批卡是该会话 composer 的顶替**（`conversation.composer`，chain/session）：原样呈现、不隐藏、不合并、不预勾选，且 `allowed-once / rejected` 两选一——**没有「总是允许」**，玄枢也不自制这个开关。
- **F1 的界面事实（必须交代）**：审批卡只在 `conversation` 面板在屏时可见。日课是定时任务、用户当时多半不在会话面板，因此设计上给两条可见性兜底：① 系统会话在 DSH 会话列表里以「玄枢 · 系统」出现，日课卡给 `[查看投递会话]` 一键切过去（`ctx.layout.selectPanel(null)`）；② 若因未决审批导致当日卡缺失，日课卡转 `error` 并写明「有一次待处理的写入审批，去系统会话处理」+ 同级按钮。
- 想长期放行只能去 DSH 的权限预设里改；本屏放一句指路文案：「长期放行请在 DSH 权限设置里改，本屏不提供跳过确认」。
- 人驱动的地方也写清楚：`[重新生成（今天）]` 会覆盖当日卡 → 弹一次轻确认（「将覆盖今天的日课，继续？」），不静默覆盖。
- token：人工闸门处用 `--xs-constraint-human-gate-fg/-bg`（只用于「人点的控件」的容器，不用于普通说明文字）；**审批卡内部不上玄枢的色**（`constraint` 族不定义审批卡 token）。

**附带说明（不属矩阵，但为本屏口径）**：不联网这条写成界面事实——A ①「不联网取外部资讯：本次内容只用底座 + 上面的时间基准」、B 区说明「所有任务只用本地内容与本地时间基准；不调用任何联网检索」，两处都**不可折叠**。
