## 1. 目的与入口

**目的**：打开玄枢，第一屏看见的是「我」——我是谁（命盘）、今天注意什么（日课）、我有什么（底稿）、去哪（快捷入口）。本屏替换 DSH 原首页（ADR-0002），DSH 原 `conversation` 面板与工作区能力**不动**。

**从哪进**

- 启动 `dsh --profile xuanshu web` → 默认面板即本屏（`overview` 为默认 main key，显式 priority 遮蔽不报错）；
- 侧栏分区「家」（D1 定案，落位见 S15）点「自我总览」行 → 回到本屏；
- 任何其它面板 → 点侧栏「家」行返回。

**去哪出**

| 控件 | 落到哪 |
|---|---|
| 命盘卡 `[看详情]` | S2 命盘卡详情（`shell.overlay` 抽屉） |
| 命盘卡空态 `[开始填写出生信息]` | S3 第 1 步 |
| 日课卡 `[看完整日课]` | S14 日课与定时任务 |
| 日课卡 `[立即生成]`（空态） | 就地触发日课生成（副作用见 §5） |
| 底稿卡 `[打开底稿]` | S13 底稿面板 |
| 底稿卡「要改就改源头」三项 | S5 谱管理 / DSH 原工作区 / S12 工作流创建向导 |
| 底稿卡 `[刷新]` | 就地触发底稿刷新（副作用见 §5） |

**相邻屏**：S4 = 本屏的首次空态（仅冷启动前出现，形态见 S4）；S3 = 点亮命盘卡的唯一入口；S15 = 谱 / 藏 / 定时任务三个管理入口的落位（本屏不承载管理入口）。

## 3. 线框说明

> 线框内一律用 ASCII 符号（`-` 代替 `·`、`->` 代替箭头、`(o)/( )` 表示单选、`...` 代替省略号），以便 diff 与终端阅读；正式文案与标点以 §9 与各节散文为准。

### 3.1 宽屏（§2.1）

- ① **命盘 / 八字卡**：卡头写「命盘 / 八字」，右上角一枚 `Tag`「只读 · 由出生信息与底座生成」（C1）。正文在上盘后显示四柱（年/月/日/时）与一行口径行「真太阳时 <时> · 钟表时 <时>」——口径行是**只读展示**，不可切换 `timeAlg`（切换需重录，走 S2 → S3）。卡片底部只有一个控件 `[看详情 ->]`，**卡内无任何编辑控件**。
- ② **日课卡**：卡头写「日课 · 今天 <日期>」（卡头只用术语「日课」）。正文三行 `宜 / 忌 / 流日`，各自最多一行、超出折行。底部 `[看完整日课 ->]` 跳 S14，`[立即生成]` 就地生成当日日课（仅 `empty` / `stale` 时出现）。
- ③ **底稿卡**：卡头「底稿」+ `Tag`「纯派生 · 不可手改」（C2）。正文两行：`关于我：<段数> 段 · 来源 <路数> 路`、`要改就改源头：谱 / 工作区 / 工作流`（三项分别是链接）。底部 `[打开底稿 ->]`（只读打开 S13）与 `[刷新]`（本卡唯一写动作，不弹确认——底稿是纯派生文件，不是人的内容）。
- ④ **快捷入口卡**：三个等宽单元格 `[问事] / [工作区] / [工作流]`，每格一行主标题 + 一行副标题（书房 / 车间 / 流水线）。右下角常驻一句边界说明「谱 / 藏 / 定时任务是管理入口，在侧栏「库」与设置里，不在本卡」（C6 ○：谱入口不混进工作区/工作流这一组）。
- 面板页眉右上角常驻「数据都在本地 ~/.dsh/xuanshu/」（C11 ○：只读展示，点击不跳转写操作；「整体拷走」说明在 S15）。

### 3.2 窄屏（§2.2）

- ① 单列顺序 = D3 的读序「我是谁 → 今天注意什么 → 我的汇总 → 去哪」，**不因窄屏而改顺序**；
- ② 命盘卡窄屏只留「四柱 + 真太阳时」一行摘要，`[看详情 ->]` 仍在，详情抽屉改为全屏覆盖层（`shell.overlay` 自适应，见 S2 §6 窄屏态）；
- ③ 底稿卡的「要改就改源头」三个跳转在窄屏折成一行文本链，避免三行占位；
- ④ 快捷入口仍一行三格，不折成两行——三入口是并列关系，折行会被误读成层级。

- `XsOverviewGrid`（自研）— 本屏根：2×2 栅格（窄屏单列），持有四卡各自的取数状态，**不做整页 loading**（D2）；挂到 main key `overview`。
  - `XsDestinyCard`（自研）— 命盘卡：读底座谱快照，渲染四柱摘要 + 口径行 + `XsReadonlyBadge`；仅 `[看详情]` 一个出口。
    - `XsReadonlyBadge`（自研，DSH `Tag` 原语承载）— 文案固定「只读 · 由出生信息与底座生成」。
    - `XsCardStateShell`（自研）— 卡级空/加载/错误三态外壳（骨架屏 / 空态 / 错误条都用它包，保证四卡形态一致）。
  - `XsRikkeCard`（自研）— 日课卡：读当日日课产物（宜/忌/流日三行）+ `[看完整日课]` + `[立即生成]`。
  - `XsDigaoCard`（自研）— 底稿卡：读 `digao.md` 头部（段数 / 来源路数 / 更新时间）+ `XsPureDerivedBadge` + 三个源头跳转 + `[打开底稿]` + `[刷新]`。

  - `XsQuickLinks`（自研）— 快捷入口：三格（问事 / 工作区 / 工作流）+ 边界说明行；**静态组件，不取数**。
  - `XsDestinyDrawerHost`（自研）— 承载 S2 抽屉的挂载点（注册进 `shell.overlay`），本屏只负责打开/关闭。
- DSH 原语（点名到原语族，不写 import 路径）：卡片外壳、骨架屏、空态、错误提示条、Tag、按钮、抽屉/弹窗容器、Tooltip、列表。

## 5. 交互流程

1. **挂载本屏** → 客户端插件把 `XsOverviewGrid` 注册进 `main` 的 `overview` key，`sidebar.panellist` 行 id `overview` 选中 → 界面进入四卡**并发取数**，每卡各自 `loading`（卡级骨架，D2）。
2. **命盘卡取数**（本地文件读，无网络、无 horosa）→ 读到 `_base/bazi.md` 快照 → `ready`；文件缺失 → `empty`；文件存在但解析失败 → `error`。
3. **日课卡取数** → 读到当日日课产物 → `ready`；今日尚无产物 → `empty`（文案见图）；产物日期不是今天 → `stale`。
4. **底稿卡取数** → 读到 `digao.md` 且 `updated_at` 不早于 base 级谱最新更新 → `ready`；文件不存在 → `empty`；早于源头更新 → `stale`。
5. **快捷入口卡** → 静态渲染即 `ready`；同时探测「底座是否已立」，据此决定问事格副标题（未立时显示「底座未立 · 会先引导你填出生信息」）。
6. 点日课卡 `[立即生成]` → **【副作用】**触发内置 skill `xuanshu:rikke`：读底座谱 + 当前时刻 → 调 horosa 推运（`mcp__horosa__*`）→ 写当日日课产物 → 投递系统会话；卡进入 `running` → `ready`。失败 → `error`（给「检查底座」跳 S15）。
7. 点底稿卡 `[刷新]` → **【副作用】**触发内置 skill `xuanshu:refresh-digao`：读三源（base 级谱 / 工作区扫描 / 工作流产物）→ 规则拼骨架与来源标记 → LLM 提炼摘要 → **原子替换**写 `~/.dsh/xuanshu/digao.md`；卡 `running` → `ready`。**无【人工确认闸门】**：底稿是纯派生文件，人不手改，故刷新不需要确认（C2）；写盘位置在界面上的可见提示为卡片副行「刷新会重写 ~/.dsh/xuanshu/digao.md」。
8. 点命盘卡 `[看详情]` → 打开 S2 抽屉（本屏不动、不重取数）。
9. 点底稿卡三个源头跳转 → S5 谱管理 / DSH 原工作区 / S12 工作流向导；本屏只发起跳转。
10. 点快捷入口 → `[问事]` 打开 main key `consult`（**S6 负责**，其中 **【副作用】**`ctx.sessions.create` + `meta.xuanshu={kind:'consult',pus:[]}` 由 S6 执行）；`[工作区]` 切到 DSH 原面板（零改动）；`[工作流]` 打开 S12（**S12 负责** `ctx.sessions.create` + seed 调 `/writing-skills`）。
11. **卡级重试**：任一卡 `error` 时点「重试」只重跑该卡取数，其它卡不动（D2 的直接含义）。

## 6. 关键状态

**每卡各自三态**（D2：卡级骨架，无整页 loading）：

| 卡 | `empty`（为什么空 + 下一步 + 指向哪） | `loading` | `error` |
|---|---|---|---|
| ① 命盘 / 八字 | 「底座还没立起来：还缺出生信息。」下一步按钮 `[开始填写出生信息]` → **S3 第 1 步** | 卡级骨架：四柱位 4 个方块占位 + 口径行 1 行占位，**不整页转圈** | 「命盘快照读不出来（文件缺失或格式不符）。」`[重试]` + `[去重新录制出生信息]`（**卡上原地弹二次确认**：文案「将重新录制出生信息并重新出盘。当前底座谱会被新结果原子替换；底稿会在下次刷新时随之更新。」按钮 `[取消]` / `[去重新录制 ->]`，确认后才进 S3——与 S2 抽屉底部**同一个二次确认**）+ `[看数据目录]` → S15 |
| ② 日课 | 「今天还没有生成日课。日课默认每天 07:30 生成。」`[立即生成]` + `[改时间]` → S14 | 卡级骨架：宜/忌/流日 3 行占位 | 「日课生成失败：底座未就绪 / 推运调用失败。」`[重试]` + `[检查底座]` → S15 |
| ③ 底稿 | 两种空因分开写：**(a)** 底座未立 → 「底座还没立起来，还没有可提炼的来源。」`[开始填写出生信息]` → S3；**(b)** 底座已立但从未刷新 → 「底稿还没生成过。」`[立即刷新]` | 卡级骨架：2 行占位 + 徽标占位 | 「底稿读不出来。」`[重试]` + `[打开底稿]` → S13 |
| ④ 快捷入口 | 结构恒有内容，**不出现无内容空态**；底座未立时以「未就绪提示条」呈现：问事格副标题改「底座未立 · 会先引导你填出生信息」，点击仍可用（→ S6 后由 S6 引导） | **不适用**：静态组件，随面板同步渲染，不设骨架（此为该卡唯一不适用三态的一项，显式说明以免被当成漏写） | 「入口目标不可用」：对应 main key 未注册时该格 fail-soft 置灰 + Tooltip 说明原因，其余两格照常可用 |

**追加态**

- `running`（日课卡 / 底稿卡）：按钮换成进行中文案「生成中⋯」「刷新中⋯」+ 卡内一行进度文本；**不锁其它卡**。
- `stale`（陈旧）：
  - 底稿卡 → 卡头一枚 `Tag`「陈旧 · 源头已更新」+ 高亮 `[刷新]`；
  - 日课卡 → 「今天的日课还没生成」（当日产物日期 ≠ 今天）；
  - 命盘卡 → 快照由旧版底座生成时，卡内一行「此盘由 horosa &lt;旧版&gt; 生成」+ `[重新出盘]` → S3（不静默当作最新）。
- 禁用态：命盘卡空态的 `[看详情]` 置灰（无盘可看 + Tooltip 说明「先填出生信息」）。
- 只读态：本屏常态——四卡**没有任何编辑控件**；命盘卡的写路径**入口有两处、同一个二次确认**（S2 抽屉底部，以及本卡 `error` 态的 `[去重新录制出生信息]`，见 §6 `error` 行与 §9 C1 ③），底稿卡的写动作只有 `[刷新]`（重算派生文件）。
- 窄屏态：单列堆叠（D3 顺序），四卡的三态形态不变；抽屉改全屏覆盖（S2）。

## 9. 硬约束在 UI 上的呈现

| # | 级别 | 界面上怎么让人看出来（具体文案与控件） |
|---|---|---|
| C1 命盘卡只读 | ● | ① 命盘卡内**没有任何输入框、下拉、开关、保存按钮**；② 卡头右侧 `Tag`：**「只读 · 由出生信息与底座生成」**；③ 本屏唯一与命盘相关的写路径是「去 S3 重新录制出生信息」，**入口有两处且都必过同一个二次确认弹窗**——S2 抽屉底部（既有）与本屏命盘卡 `error` 态的 `[去重新录制出生信息]`（文案见 §6 `error` 行）；**本屏常态（`ready`）下卡上没有任何写入口**；④ 本屏空态出现 `[开始填写出生信息]` 属首次录入，不是修改；⑤ `stale` 时给的是 `[重新出盘]` 而不是就地编辑。 |
| C2 底稿只读（纯派生） | ● | ① 底稿卡内无编辑入口；② 卡头 `Tag`：**「纯派生 · 不可手改」**；③ 卡内固定一行**「要改就改源头：谱 / 工作区 / 工作流」**（三项可点，分别跳 S5 / 工作区 / S12）；④ 卡内按钮只有 `[打开底稿 ->]`（只读打开）与 `[刷新]`（重算派生文件），没有「编辑 / 保存 / 另存」。 |
| C3 藏不可见 AI | ○ | 本屏**不出现藏卡片、不出现藏条目**；侧栏「库」分区里的藏入口在此屏只是一行导航，**不带任何 AI 动作**（无「让 AI 看看」、无摘要、无问答）；首屏不出现「藏」的 AI 相关文案。 |
| C6 谱与工作区/工作流并列独立 | ○ | ① 快捷入口卡的三格 = 问事 / 工作区 / 工作流，**不在这三格里混入「谱」**；② 卡内常驻边界句：**「谱 / 藏 / 定时任务是管理入口，在侧栏「库」与设置里，不在本卡。」**；③ 若后续把谱入口放进首屏，必须与工作区/工作流分成两个视觉分组（分组规则见 S5/S15）。 |
| C11 一切数据本地、可整体拷走 | ○ | 面板页眉常驻一行只读路径展示：**「数据都在本地 ~/.dsh/xuanshu/」**；本屏不提供任何删除/导出写操作，「整体拷走」的完整说明落在 S15。 |
