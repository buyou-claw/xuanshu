# 自我总览与命盘

用户从总览了解玄学底座状态，首次录入出生信息并查看只读命盘。依据仓库 S1–S4 界面稿。

## Sub-features

- `overview-empty` 空底座在总览上给出开始入口。
- `bazi-onboarding` 填写并核对出生信息后出盘。
- `mingpan-revisit` 从独立入口回看四柱。

## How to get to it (user POV)

侧栏「总览」进入「家 · 自我总览」。空底座可由命盘卡「开始填写出生信息 ->」进入，也可直接点侧栏「填八字」。出盘后，从侧栏「命盘」回看详情。

## Driving it with scripts/experience

前置为合成出生信息、新 home 和运行中的实际 horosa 服务。按仓库 horosa 手册确认同一实例使用的端口与服务状态。

- **找到入口。** 观察「家 · 自我总览」中的命盘空卡。若有多个同名按钮，先查看卡片语境。现有协议在重名按钮没有可定位的可访问容器时无法消歧，记录总览卡入口受阻。独立检查侧栏 `{role:"button",name:"填八字"}` 能否打开「八字冷启动向导」。
- **录入并核对。** 按向导的可见字段填写虚构日期、当地时间、地点、时区和必填项。截图记录时间与地点复核。勾选「以上信息我已核对」，在用户确认后点击「确认并出盘」。记录实际完成或服务错误。
- **回看。** 按界面提供的「跳过」或「完成，回总览 ->」返回，核对命盘卡有内容。从「命盘」打开详情，确认「② 四柱」及实际四柱。只读核对同一 home 的 `xuanshu/bazi/snapshot.json` 和 `xuanshu/bazi-snapshot@1`。

## Gotchas

- 空底座时命盘卡和底稿卡都可能显示「开始填写出生信息 ->」。侧栏路径跑通后，卡片路径仍需单独覆盖。
- horosa 端口空闲只证明当前无人监听。实际服务缺席时出盘任务记为受阻，保留填写与错误态的独立证据。跳过接 AI 的路径只证明出盘和回看。
- 使用合成出生信息。进入澄清闸后沿可见路径处理，未经确认的值不能算已保存。
- 实际启动 horosa 时，关闭 Web 实例后再核对同一 home 的 `xuanshu/horosa/horosa-status.json` 和对应端口。按 `docs/runbook/horosa.md` §2 的 `serve.started`、`pid`、端点和进程归属判断。复用的服务保留，只有归属确认是本轮启动的进程才按手册关停。归属不明时记录残留状态。
