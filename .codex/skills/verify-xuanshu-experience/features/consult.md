# 问事与历史

用户在问事里得到一场真实问答，之后从历史找回同一场会话。依据仓库 S6、S7 界面稿。

## Sub-features

- `consult-start` 发起一场问事并获得真实响应。
- `consult-find` 通过标题或首句搜索历史，查看原问答。
- `consult-continue` 从历史回到同一会话。

## How to get to it (user POV)

从侧栏「问事」进入。自我总览也有问事快捷入口，缺模型时可能置灰并解释原因。「历史回看 ▸」进入搜索与只读视图。

## Driving it with scripts/experience

前置为独立 home 中配置的实际测试模型，及一段无个人信息的唯一合成问题。需要确认或审批时按真实 UI 办理。

- **发起。** 观察侧栏 `{role:"button",name:"问事"}` 和门厅。通过「这一次想问什么」「＋ 开一次问事」走可见发起流程，记录真实提交、回复完成以及会话标题。总览快捷入口另测。
- **找回。** 点「历史回看 ▸」，从实际可访问树找到「搜索 会话标题 / 首句」并输入本轮标题或首句。打开对应结果，核对「【只读 · 不可编辑】」和同一问答。需要继续时通过「继续这次问事 ▸」确认仍是同一会话。
- **证据。** 保存提交、回复和历史截图及轨迹。使用界面标识与独立 home 中 `xuanshu/consult/sessions/<sessionId>.json` 和对应会话日志交叉核对。仅有旁挂元数据不足以证明模型已回复。

## Gotchas

- 空 home 的历史空态可独立观察。无可用模型或无真实回复时，正常问答、成功历史及继续问事保持受阻。
- 区分 `session-xs-consult-*` 和普通会话。当前「导出选中」「删除」置灰是历史面的既有边界。
- 真实模型和工具行为只在测试配置中使用，按任务范围保留审批。
